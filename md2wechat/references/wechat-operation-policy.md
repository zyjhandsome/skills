# WeChat 公众平台运营规范 gate

两种模式在动笔之前都必须读完本页，并先跑源稿扫描。覆盖完整不能压过可发布。

官方原文（动态文档，以微信当前页为准）：

- [《微信公众平台运营规范》](https://mp.weixin.qq.com/cgi-bin/readtemplate?t=business/faq_operation_tmpl&type=info&lang=zh_CN&token=)
- [《微信公众平台服务协议》](https://mp.weixin.qq.com/cgi-bin/readtemplate?t=home/agreement_tmpl&type=info&lang=zh_CN&token=)

后台删文常用措辞是「违反《微信公众平台运营规范》中的法律法规和政策」。对应规范里的发送内容规范（第 4 节）、谣言/误导（4.9 / 4.11）、侵权与商业秘密（4.1），以及「遵守当地法律监管」：不得把腾讯卷入政治和公共事件。无新闻信息服务资质的账号，不能把未核实传闻写成新闻。

扫描器只做机械信号，不能证明合法。有 `stop` 信号时，先改写或停交付，再谈成稿。

```powershell
python "$env:USERPROFILE\.cursor\skills\md2wechat\scripts\scan_wechat_policy.py" "<整理文档.md>"
```

退出码 1 表示源稿带发布阻断风险。不要继续生成 HTML，除非已经改到扫描通过，或结论是「不可发布」并停止交付。

## 先判断，再写作

| 源稿主料 | 结论 | 做什么 |
|---|---|---|
| 公开讲座、发布会、已公开采访；观点可归因；数字已核实或明确是口播 | 可发布 | 沿用源稿 H1/H2 与各节判断；不要为更好听另写标题 |
| 有未核实传闻、标题党、转载侵权，但删掉后仍有一条公开主线 | 改写后可发布 | 删风险主张；**仅当源稿 H1 本身触碰 4.11** 时改标题，否则仍用源稿 H1 |
| 主料是闭门会/内部会外泄全文、未证实融资/估值新闻、落马官员关系、或会把账号拖进政治公共事件 | 不可发布 | **停交付**。不写 HTML，不写封面 |

`full` 模式不能用来整篇重印被阻断的主张。政策先于覆盖：该删就标 `删除`，理由写「运营规范」；删不掉就停。

改写成稿**不能**把外泄材料合法化。归因到「知情人士」「彭博社尚未核实」也**不能**把融资传闻变成可群发新闻。

禁止用特殊符号、拆字、谐音、截图长文规避审核。这本身就是规范 3.13.4。

## 和这篇技能最相关的条款

只处理图文正文，不处理注册、刷粉、模板消息。

- **4.1 侵权 / 商业秘密**：未经授权发送他人原创、身份证等隐私、企业商业秘密。闭门投资人交流、主持人要求「不要外传 / 不要录屏」的卡量与财务数字，按未经授权的内部信息处理，不要当「全文整理」群发。
- **4.9 谣言类**：不实信息，可能损害他人或企业。公司未确认的「暂停融资」「估值」「暴雷」，即使用「据报」也仍是在传播。
- **4.11 误导类**：夸张惊悚标题、题文不符、断章取义、旧闻翻炒。「外泄(全文)」「突然暂停」「心虚」「震惊」「爆料」属于这一类。
- **4.12 其他违法违规**：抓不住 4.1–4.11 时，平台常用「法律法规和政策」兜底。
- **当地法律监管**：避免让平台卷入政治和公共事件。落马官员「关系密切」这类第三方政治联想，即使稿子写「不采信」，也不要写进将要粘贴的正文。
- **3.13.3 / 4.11**：长期标题党、谣言类会被升级处罚。

服务协议还禁止散布谣言、虚构事实隐瞒真相。运营者对所发内容负责。

## 写作时怎么处理

默认沿用源稿 H1。不要为转发另写金句。源稿 H1 已含外泄、全文、突然、震惊、心虚、爆料、内部录音时，才改标题，并加 `--allow-heading-rewrite`。新标题仍只承诺源稿里已经公开、已核实或可明确归于公开讲者的那一条判断。

正文只保留公开场合的讲者观点，并继续归因。删掉：闭门会逐字转写当「全文」、未证实的融资/交易进展、政治人物关系、主持人要求保密的卡量/配额/财务细节。

来源与说明仍只写 `原文：{原标题}`。不要在页脚堆免责声明来「对冲」违规内容；免责声明不能让不可发布的材料变成可发布。

## 审计里必填

覆盖审计增加一节，不要单独存成交付文件：

```markdown
## 运营规范
- 官方页：微信公众平台运营规范（发送内容规范 + 当地法律监管）
- 扫描：列出 scan_wechat_policy.py 的风险码，或写「无」
- 处理：改写了什么 / 删除了什么 / 为何停交付
- 发布结论：可发布 | 改写后可发布 | 不可发布
```

源稿仍有 `stop` 风险时，不得写「可发布」。结论是「不可发布」时，不得输出 `*_公众号文章.html` 和封面。

## 生产反例（必须停）

`20260725 梁文锋4小时讲话外泄(全文)，DeepSeek突然暂停第二轮融资_整理文档.md` 已按本流程做过公众号，后台提示违反《微信公众平台运营规范》中的法律法规和政策并被删除。

同时踩中多条，任何一条都够停：

1. 主料是闭门投资会外泄转写，主持人明确要求不要外传数字、不要录屏。
2. 「突然暂停第二轮融资」来自知情人士口径，公司与讲者未公开确认，彭博社亦写尚未核实帖文真伪。
3. 第三方把讲者与落马官员绑在一起；即使标注「不采信」，也不应出现在将粘贴的正文里。
4. 原标题用「外泄(全文)」「突然」做传播点，属于 4.11 误导类。

正确动作：告诉用户这篇源稿不能作为微信公众号成稿交付，列出上表对应条款，**不要**再排一版「去标题党但仍是泄稿+融资传闻」的 HTML。用户若只要本地知识库，用整理文档本身，不要走本技能的粘贴交付。

## 常见借口

| 借口 | 实际 |
|---|---|
| 「已经归因到知情人士」 | 归因不等于可发布。4.9 管的是传播不实信息。 |
| 「full 要完整保留」 | 政策先于覆盖。保不住就停，不能整篇重印泄稿。 |
| 「editorial 改写过就不算外泄」 | 主料仍是未经授权的闭门会内容时，改写只是换皮。 |
| 「页脚写了不代表官方立场」 | 免责声明不能对冲 4.1 / 4.9 / 政治公共事件。 |
| 「先出 HTML，用户自己决定发不发」 | 本技能的交付物就是粘贴稿。不可发布就不要产出 HTML。 |
| 「拆字/谐音/截图可过审」 | 3.13.4 禁止规避审核。 |
| 「扫描没报错就一定能发」 | 扫描是机械门禁。政治、资质、时政新闻还要人工判断。 |
