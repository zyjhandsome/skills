# 六层判定阶梯

自下而上：下层不通过，上层结论没有意义。报告按层分组，就是为了让人一眼看出
"是没跑起来、还是功能坏了、还是只是样式漂移"。

## L0 可达性与运行时错误

**采集**：HTTP 状态码、控制台 `error`/`pageerror`、`requestfailed`、HTTP ≥ 400 的响应。

| 现象 | 判级 |
|---|---|
| 任一侧主文档 HTTP ≥ 400（即使两侧相同） | 阻断且**证据作废** |
| 两侧成功状态码不同 | 阻断 |
| 某侧采集异常（超时、导航失败、`waitFor` 未命中） | 阻断且**证据作废** |
| 状态准备动作失败 | 阻断且**该状态证据作废**，不得继续截图冒充目标状态 |
| 落地 URL 命中登录/SSO 特征（`assertLanded`） | 阻断且**证据作废** |
| 某侧登录动作失败 → 整侧作废 | 阻断且**整侧作废** |
| 候选侧新增 JS 报错 | 阻断 |
| 候选侧新增失败请求 | 默认重要；主文档导航失败阻断；可按 `runtimePolicy` 配置 |
| 动作后 `waitFor` 未命中（可能是有意离开锚点） | 参考（告警） |
| 基线有、候选已消失的报错 | 参考（通常是修好了） |

L0 有阻断项时，**上层所有"通过"都不可信**，先修再比。

失败请求会保留资源类型、所属 frame 和是否导航请求。只在用户确认某个请求不属于验收面后，
才可用 `runtimePolicy.ignoreRequestPatterns` 降为参考；通用 Skill 不内置产品路径白名单。

**"作废"与"失败"不是一回事**：作废意味着我们没有采到目标页面，因此该状态**不参与**
L1–L5 比对，报告顶部单独列出。此时不允许给出"一致 / 不一致"的判断——只能报告
"采不到，原因是 X"。把作废当成 0 差异（或当成一堆差异）都是错的。

## L1 功能行为（用户流程）

**采集**：`journeys` 里每一步的执行状态，以及 `expectCount` / `expectText` /
`expectValue` / `expectUrl` 的观测值。两侧跑**同一份步骤脚本**。

| 现象 | 判级 |
|---|---|
| 同一步在两侧成败不同 | 阻断 |
| 两侧执行步数不同（新版中途断了） | 阻断 |
| `expectUrl` 归一化后仍不同 | 阻断 |
| 流程无法开始（落地登录页 / `waitFor` 未命中） | 阻断且**证据作废** |
| 流程结束在登录/跳转页 | 阻断且**证据作废** |
| 其他观测值不同（文本、计数） | 重要；仅 `dataDependent: true` 且 `different-data` 时降为参考 |
| 流程中候选侧新增控制台报错 | 重要 |

这一层是**唯一**能证明"功能一致"的证据。没有 journey 就不要写"功能一致"。

两条降噪口径，避免把迁移的正常变化报成缺陷：

- **`expectUrl` 先归一化再比**：`pathOverrides` / `<side>Path` / `urlTokens` /
  `urlNormalizeRules` 里声明过的路径会被换成占位符，声明过的路由迁移因此相等；
  归一化后**仍然**不同才阻断，那说明是没声明的跳转差异（可能真跳错页了）。
  只关心参数不关心路径时，给该步加 `ignorePath: true`。
- **`expectCount` 只数可见节点**：旧框架 `ng-hide`/`v-show` 把隐藏项留在 DOM，
  新框架 `v-if` 直接不渲染；连隐藏一起数会凭空报出"6 对 5"。原始总数记在
  `observedTotal`，只作附注。

## L2 语义结构与内容

**采集**：`dom.json` 的语义摘要 — 标题层级、可点按钮（含禁用态）、表单字段
（name/label/placeholder/required/disabled/options）、表格列名与行数、可见链接、
图片加载结果、叶子节点文案。

| 现象 | 判级 |
|---|---|
| 基线有、候选缺失的按钮 | 阻断（功能入口丢了） |
| 基线有、候选缺失的表单字段 | 阻断 |
| 表格列定义变化（增删改名） | 阻断 |
| 标题结构变化 | 重要 |
| 候选新增按钮/字段 | 次要（多半是有意变更，需用户确认） |
| 表格行数不同 | 重要；`different-data` 时降为参考 |
| 缺失链接、可见文案差异 | 重要/次要；`different-data` 时降为参考 |
| 候选侧图片加载失败（naturalWidth=0） | 重要 |

**注意**：迁移中"列名从『客户名称』改成『客户』"会被判为阻断。这是**故意**的严格口径 —
要么改回去，要么由用户签字确认为有意变更。技能自己不做这个判断。

**iframe**：显式 `compareSurface.frame/root` 时，只摘要声明的业务表面；整页兼容模式才覆盖
主文档 + 所有可读 iframe（托管页的顶栏/菜单通常在 iframe 里）。
若某个 iframe 读不到（`sandbox` 禁脚本、已 detach），它会以 `iframe 不可读` 记一条参考项，
并把该状态的"缺失"类判级**降一档**（阻断→重要，重要→参考）并附提示：
那是"读不到"，不是"没有"，必须人工看截图确认。反过来说，报告里出现
`iframe 不可读` 时，该页的 L2 结论就不是完备的，结论里要写明。

## L3 布局几何

**采集**：探针元素的 `getBoundingClientRect`、landmark 位置、文档总高度。

| 现象 | 判级 |
|---|---|
| 基线可见、候选不可见的探针 | 重要 |
| 尺寸差异同时超过 `layoutTolerancePx` 与 `layoutToleranceRatio` | 次要 |
| 文档总高度差异 > 5% | 次要；`different-data` 时降为参考 |

双阈值（绝对 px + 相对比例）是为了避免小元素 1–2px 抖动刷屏。

## L4 计算样式

**采集**：每个探针首个可见元素的 30 项计算样式（字体族/字号/字重/行高、前景/背景色、
边框、圆角、阴影、间距、display/flex/grid、transform 等）。

| `styleIntent` | 判级 |
|---|---|
| `pixel-parity` + 命中高影响属性（font-family / font-size / font-weight / color / background-color / display / line-height） | 重要 |
| `pixel-parity` + 变化项 > 6 | 重要 |
| `pixel-parity` + 其他 | 次要 |
| `redesign-allowed` | 一律参考 |

这一层比像素层**更可执行**：它直接给出"`border-radius: 4px → 10px`"这种能定位到
CSS 变量或组件主题的结论，而像素差异只告诉你"这一块不一样"。

**降噪**：同一个属性在 ≥3 个探针上一起变（`thresholds.styleAggregateMinProbes`），
收敛成一条"全局样式漂移 `<属性>`"，并从逐探针条目里剔除 —— 那是一次主题/令牌改动，
不是 N 个缺陷。壳层探针（`body`/`button`/`link`）在托管页上噪声很大，
可用 `defaultProbes: false` 或只挑子集，再用 `styleProbes` 指向真正关心的业务组件。

默认探针只量主文档；配置 `compareSurface.frame` 后，L3/L4 会在选中的 iframe/root 内执行。

## L5 像素外观

**采集**：同视口截图，逐像素比较（通道差 > `pixelChannelTolerance` 记为不同），
输出差异图（灰底 + 品红标记）、差异比例、变化包围盒、24×24 网格热点区域。

| 现象 | 判级 |
|---|---|
| 差异比例 > 阈值 × 10 | 重要 |
| 差异比例 > `pixelDiffRatio` | 次要 |
| 截图尺寸不一致 | 次要（同时说明布局或滚动条差异） |
| `pixel-parity` 下截图缺失、解码失败或像素工具不可用 | 阻断且该状态的视觉证据作废 |

像素层容易被字体渲染、滚动条、动画残留污染。默认已做的稳定化：禁用动画与过渡、
隐藏光标、`reducedMotion`、等待 `document.fonts.ready` 与短时 `networkidle`、
固定时区/locale/缩放、可选冻结时间与随机种子。仍然漂移的区域应加进 `masks`。

## 总体结论口径

| 结论 | 条件 |
|---|---|
| ⛔ 无法判定 | `evidenceStatus=partial/invalid`：存在作废证据或采集契约不一致 |
| ❌ 不一致 | 存在任一 `block` |
| ⚠️ 有重要差异 | 无 `block`，存在 `major` |
| ✅ 通过 | 只剩 `minor` / `info` |

- 报告同时输出 `evidenceStatus` 与 `parityVerdict`。前者回答“证据是否完整”，后者只回答
  “有效证据范围内是否对等”；证据不完整时顶层 `verdict=inconclusive`，不能被 block 数量误写成完整失败结论。
- `block` 必须修复或由用户书面确认为有意变更后才能改判。
- `major` 需逐条给出"修复"或"已确认为有意变更"的处置。
- `minor` / `info` 由负责人签署接受。

**结论必须带边界**：写明覆盖了哪些页面、状态、视口，以及 `dataParity` 与
`styleIntent` 的取值。没有跑 journey 就不能说"功能一致"；`different-data` 就不能说
"内容一致"；`redesign-allowed` 就不能说"视觉一致"；有作废状态就不能说"整个模块一致"，
有 `iframe 不可读` 就不能说该页"结构完整比过了"。
