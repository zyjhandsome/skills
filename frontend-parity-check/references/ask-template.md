# 提问模板

## 登录问题的默认选项

用 `AskQuestion` 时，下面 4 个 label **必须逐字使用**（第一项放首位并标推荐）。
不要改写成「自动探测加我手动登录」，也不要砍成 3 项。用户没有特别偏好时就采用第 1 项：

1. **我来登录，完成后回复「已登录」（推荐）** — 先短探测；未就绪就弹出专用窗口。你在窗口里登录，完成后在对话回复「已登录」，脚本立刻保存会话。不要发密码。
2. **免登录直接可访问** — 仍会验证是否静默跳转到 SSO。
3. **从我的浏览器导出会话** — 复用已经打开且登录好的浏览器，需要 CDP 调试端口。
4. **提供测试账号** — 适合稳定且无扫码/MFA 的自动化账号；密码通过环境变量提供。

交互组件自带的 `Other/其他` 保留。第一项不要求用户提供密码、不复用日常浏览器 profile。

## 登录状态机（SKILL.md 只留配方，细节在此）

`auth.mode=auto-interactive` 时按 **baseline → candidate** 逐侧处理，不要同时弹两个窗口，
也不要先自己打开目标站探究。

固定顺序：**已有 `storageState` → 无头验证 → 通过则静默结束 → 失败才开窗。**
用户说「我来登录」只保证第三步会开窗，**不跳过复用**。已有会话仍有效或页面免登录时，
`prepare-auth` 会在几秒内无头结束。

```bash
node scripts/prepare-auth.mjs --config <file> --side <side>   # 必须后台运行
```

- 不要加 `--skip-probe`（自检/调试专用）。
- 不要因为用户说了「我来登录」就加 `--force-interactive`——该开关只表示「未就绪必须开窗」，
  仍先探测。
- 采集因 SSO 作废后重跑：先 `prepare-auth`（不加 force / skip-probe）。探测失败再开窗。
- 专用浏览器使用 Skill 独立 profile，不复用用户日常 Chrome/Edge profile。
- 「我已经在浏览器里登录了」**不等于**脚本已登录；若用户坚持复用现有窗口，才使用
  `scripts/export-storage-state.mjs` 的 CDP 方案。
- 说「免登录」也要验证：内网站点经常静默跳 SSO。短探测通不过就开窗，不要自己点站排查。
- 重复执行同一 side 时，脚本会复用仍在等待的窗口并拒绝再开一个。

只有脚本输出 `LOGIN_WINDOW_READY`（且 `visible:true`）后，才可以说窗口已经创建。
「准备创建」不是成功；若进程先退出，直接回报启动错误，禁止让用户寻找不存在的窗口。

确认开窗后**立刻结束本轮**，告诉用户准确的 side 和目标地址：

**已创建 `<side>` 登录窗口，目标为 `<targetUrl>`。请在该窗口登录；完成后回复「已登录」。
不要把密码发给我。若窗口未置顶，请从任务栏或 Alt+Tab 打开。**

不要称「最新窗口」。**禁止**说「不用回复」。**禁止**在同一轮对话里死等 `timeoutMs`
（默认 10 分钟）。

用户回复「已登录」后立刻执行，且只对当前正在等待的 side：

```bash
node scripts/prepare-auth.mjs --config <file> --side <side> --confirm
```

`--confirm` 只接受仍有活跃登录进程的 side；孤立或过期确认会被拒绝，不会污染下一轮。
脚本收到确认会马上校验并保存；未就绪、仍停在 SSO、或冷启动失败时立刻退出并打印原因，不再干等。
超时、窗口被关闭、或确认后仍未就绪时不得继续采集。页面自己回到目标页并命中 `waitFor`
时仍会自动保存。

`waitFor` / `interactive.readySelector` 必须是登录后才出现的节点。禁止用整页壳、
`#app` / `#root`、Header、面包屑、登录前就有的标题；也不要用「必须有数据行」的选择器
当登录成功。登录前会先画出的壳节点当成功，会把空会话存成 `ready`，采集立刻被打回 SSO。

## 用户可直接照抄的提问

把下面这段发给 AI，一次把必要信息给全，避免来回追问：

```text
帮我做前端一致性验收（用 frontend-parity-check 技能）。

【两个地址】
- 升级前 baseline：https://old.example.com
- 升级后 candidate：https://new.example.com
- 路由差异：旧 /order/list.html → 新 /order/list（其余同名）

【比较面】
- 整页都要一致 / 只验业务页体
- 旧版业务页在 iframe#business-frame 内、根节点 #order-app；新版在主文档 #order-app
- 已确认不属于验收面的宿主区域：.global-header、.aside-wrapper

【登录】
- 首选：请先自动探测；需要登录时打开专用窗口，我登录后回复「已登录」
（或：不需要登录 / 从我已经打开的浏览器导出会话 / 提供测试账号
 / 我提供 storageState 文件：./auth/baseline.json / 其他）

【要比的页面和状态】
1. 订单列表 /order/list：默认态、输入"A001"查询后、状态下拉展开
2. 订单详情 /order/detail?id=1：默认态

【要验的用户流程】
- 列表输入关键词 → 点查询 → 行数变化 → 点"查看" → 详情面板出现、标题正确
- 若按钮会打开新窗口：请明确要求验证 popup 中的 URL、标题和关键内容

【判定口径】
- 两侧数据源：同一套测试库（same-data） / 各连各的（different-data）
- 样式要求：必须视觉对齐（pixel-parity） / 本次允许改版，只卡功能（redesign-allowed）
- 视口：1440x900、1280x800
- 需要忽略的动态区域：右上角时间戳 .update-time、顶部进度条 #nprogress

【环境】
- Playwright 已装 / 没装（没装的话请先告诉我怎么装，我确认后再执行）
- 内网 + 公司代理/自签证书，装不了官方浏览器内核 → 可以用我本机的 Chrome/Edge

输出：分层报告 + 差异图路径 + 阻断项清单，并区分「回归缺陷」和「有意变更」。
```

## 信息不全时的追问顺序

按对结论影响从大到小追问，一次问完，不要挤牙膏：

1. **两个 URL、路由映射与比较面** — 缺这个无法开工；路由不同必须写进 `pathOverrides`，
   否则地址差异会被判为跳转缺陷。
   一侧是壳 + iframe、另一侧是独立页时，必须问清 iframe/root，不能默认整页硬比。
2. **登录方式** — 默认第 1 项。完整状态机见上一节；不要在追问里改写 4 个 label。
   备选才是免登录、导出会话、测试账号。只有用户明确要复用已经打开的浏览器时，
   才走 `scripts/export-storage-state.mjs`。
3. **`dataParity`** — 决定"行数/文案不同"算缺陷还是噪声，直接改变结论措辞。
4. **`styleIntent`** — 决定"按钮颜色变了"算问题还是预期。
5. **要覆盖的页面 / 状态 / 流程 / popup** — 决定结论的适用边界。
6. **视口与需要遮罩的动态区域** — 决定像素层是否可信。

## 一句话就能启动的最小提问

信息不全但想先跑起来时，用户至少要给到：

```text
比一下 https://old.example.com/order/list 和 https://new.example.com/order/list
功能和样式是否一致，不需要登录，两边连的是同一套测试数据。
```

此时的默认取值必须在报告里写明：单视口 1440x900、只比默认态、无 journey、
`dataParity` 按用户所述、`styleIntent=pixel-parity`。
并在回报时明确提示：**没有跑用户流程，功能一致性只覆盖到静态结构层。**

## 用户常见的错误提法与纠正

| 用户这么说 | 问题 | 纠正 |
|---|---|---|
| "截个图对比一下就行" | 只有 L5，漏掉功能与结构 | 说明像素通过不等于功能一致，补一条 journey |
| "跟设计稿对一下" | 没有 baseline URL | 这是设计走查，不是 parity；本技能需要两个可运行地址 |
| "线上老版对本地新版" | 数据源与网络环境不同 | 明确设为 `different-data`，并说明结论的边界 |
| "全站都比一遍" | 覆盖面无限扩张 | 先选 2–3 个最有代表性的页面（含搜索+表格），跑通再扩 |
| "不用登录，直接开就行" | 内网站点常静默跳 SSO | 先自动探测；若确实跳 SSO，打开专用窗口让用户登录，不拿登录页出结论 |
| "我浏览器里已经登录了" | Playwright 是干净会话，不共享 | 默认仍开专用窗口登录，完成后回复「已登录」；用户明确要求复用原窗口时才走调试端口导出 |
| "登录了怎么还在转" | 脚本在等就绪选择器/冷启动，不是在等你输入密码 | 回复「已登录」触发立刻校验；未就绪会打印 URL 和原因，不再干等 |
| "地址不一样是正常的，你别管" | 不声明就会被判跳转缺陷 | 把新旧路径写进 `pathOverrides`，让脚本知道这是有意迁移 |
| "顺便验一下无障碍/读屏" | 本技能不验 a11y | 改走专门的无障碍检查，不要写进 parity 结论 |
| "手机实机也要比" | 只用 Playwright 视口 | 结论写明不是真机；需要真机就另开流程 |
| "图表画得对不对" | Canvas/WebGL 内容验不了 | 把画布写进 `masks`，只验容器几何/周围控件 |
