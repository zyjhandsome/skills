# 内容结构化整理（Content Structuring）

## 你要做的事

把原始素材重构成一份读者**不必回到视频、播客或原文**也能掌握绝大多数关键信息的 Markdown 文档。你不是写读后感式摘要，而是做语义级的**全息降噪重构**：论点、数据、案例、步骤、推导、主持人追问、嘉宾语言风格和关键语录都要落地。

默认输出为中文，体裁是兼顾结构化与可读性的**深度文章版**。**信息型多人播客、访谈、圆桌 Q&A** 默认采用「**对谈三层节结构**」：每节 **核心洞察 → 深度解析 → 对谈实录**（篇末省略独立关键语录节，金句沉入实录）。若核心嘉宾存在明确的**旧判断 → 触发证据 → 新判断 → 组织实践 / 制度方案 → 个人行动**，仍用对谈三层，但按这条**立场演化轴**合并相邻问答，禁止把每个主持人问题机械拆成一节。若素材存在**持续分歧、连续追问、拒绝回答、纠错或立场升级**，改走「**争辩型访谈 / 原声增强模式**」：按原始交锋顺序组织，每节 **原声交锋 → 语境与释义 → 未决问题（按需）**，不得先用编者结论压平双方立场。**成稿即中文**：叙述层与**对谈实录/原声交锋/关键语录**均直接用中文写；仅当用户显式要求「保留英文原文 / 中英双语」时才覆盖引语语言。用户可显式要求专栏文章模式、纯粹对话模式、不要对谈实录、简洁版等。

当用户**指定跨文化受众**（如「中国公民、赴美大一、熟悉课堂英文但不熟悉美国文化梗与高校语境」）或素材文化梗密集时，可启用**可选的「受众可读性内化适配」**：首次出现处补文化/人物/语境背景、客观第三人称口吻、**禁元叙述/禁「你们」说教/禁国内场景硬类比**，且**不降信息密度**——详见 `references/language-and-gates.md`「可读性内化适配（受众导向，可选）」。

## 默认中文化（必读摘要）

| 写什么 | 默认语言 |
|--------|----------|
| 导读、目录、正文、核心洞察、**对谈实录 / 关键语录** | **中文**（直接用中文写，禁止先英后译式夹写） |
| 公司/产品/API/**Agent Skill** 等专名，以及 AI/DevTools 的社区原生概念标签 | **保留英文或中英并写**（禁止过译，见下） |
| 元数据「原标题」、术语表专名列 | 可保留英文 |

**过译红线**：整理 Cursor / Claude / Agent 工具向素材时，不只产品专名要保留英文，讲者用来命名**角色、范式、工作流原语或对照组**的社区原生标签也要保真。**Skill / Agent Skill / Skill Creator / Hooks / Computer Use / Composer / Canvas / Subagent** 保留英文；**Builder、Agent、Agent Loop、Loop、Graph、Workflow、Harness、Evals** 等在承担概念标签时也保留英文，首次可补一句中文释义。❌ 不要把 `Agent → Loop → Graph` 抹平成「代理→循环→图」，也不要因 4c 词库命中就机械翻译。普通动作、状态和形容词仍写中文；同一个词按指称判断。细则见 `references/over-translation-guard.md`。

**成稿后必做**：跑 `scripts/selfcheck.py {稿}`（一次给出 4c-1 / 4c-2 / 4d）。4c-1 裸词须清零；4c-2 连续英文须逐条核实（译中文或确认为专名）；4c-3 独立扫实录/语录；过译护栏反向检查。`CONTEXTUAL` / `OVER_TRANSLATION` 是人工复核，不是机械替换。把机检行贴进自检，**未核实不得标 ✅**。再抽 3 个原文片段做「信息覆盖抽样」。存量稿：**最小 diff**，见 `language-and-gates.md`。

## 可读性硬指标（4e，v5.37）

`selfcheck.py` 会输出「可读性机检」行。三层结构最常见的失败，是解析把实录换成第三人称再讲一遍。

| 指标 | 阈值 |
|------|------|
| 解析与实录字面重合（8 字片段） | ≤20% |
| 解析篇幅 | ≤ 同节实录的一半，通常 200–400 字 |
| 单节总长 | ≤3500 字；超了就拆节或把问答归位 |
| 单段 | ≤300 字；实录在话题转换处断段 |
| 事实边界 | 出现在 ≤60% 的节，只标易误读的句子 |

现场零散问答先并入所属主题节，禁止堆成杂项收尾节。ASR 纠错只进自检，不进术语表。细则见 `language-and-gates.md`「4e 可读性闸门」。

**压缩不等于删除（4f，v5.38）。** 为过 4e 压缩解析时，解析里独有的事实、例子和限定句要移进实录，不能一起删掉。移进去的必须是该讲者的原话。解析里的第三人称叙述（「他描述」「正文不写成」「转写里」）留在解析，或收成一节末尾的 `> **事实边界**`，不得套上 `**全名**：「…」`。修订已有稿前先另存副本，改完跑 `selfcheck.py 新稿 --before 副本`，按「修订完整性」清单从上往下补回真丢失的内容。

**括注是原子块（4f-3，v5.41）。** `[编者注：…]`、`［编者注：…］` 和事实边界整段保留、同一段内收口。扫读断段、压缩解析、把句子移进实录，都不得从括号中间切开，不得把收口的 `]` 单独成行或写成 `「]」`。括注里的句子是编者口径，不是发言。ASR 纠错仍只进自检。细则见 `language-and-gates.md`「括注与编者句子」。

**扫读呈现（v5.40）。** 段长合格仍可能不好读。读者必须自己切开「谁是谁、第几步、哪边对照」时，按 `editorial-standards.md`「扫读呈现」换行、改成列表或表格，或补一张小图。对照表列少、格子写短语，外沿与正文同一栏，整理稿不另写宽度。因果和声口仍写成段落。人物背景里，场上每人一段，未出场名单再单独一段。导读一条标签后若并列三件以上的事，写成一句加列表。深度解析承担不展开实录也能读完一节的对照、步骤和场合，不写成一句图说，也不把实录再讲一遍。实录在话题转换处断成下一行引语。

**节标题不写序号（v5.42）。** 正文 `##` 用实质性标题，不要写成 `## 1. …`。顺序只出现在 `## 目录` 的有序列表里。讲稿页会再给正文章节画 01、02；标题里再写「1. 」就会叠成两套序号。标题本身以数字起头、但不是「一到两位数字 + 句点 + 空格」的，保持原样，例如 `12%`、`2012 年`、`66 岁`。存量稿不必为这条回头改标题；`md2html-lecture` 输出时会剥掉这种前缀，锚点仍按原标题生成。

## 技术素材与多源合并

- **AI/DevTools 行话**：整理 AI 编码、开发者工具类素材时，4c 须额外 grep「AI/DevTools 行话簇」。**判定原则**：产品/命令/协议/模型名，以及承担角色、范式、工作流原语或对照组的社区原生标签（如 `Builder`、`Agent Loop`、`Loop`、`Graph`）保留英文或首现中英并写；**普通行为、状态、口语形容词**中文化。若原文把若干词并列成一套 taxonomy，整组保留，不拆散翻译。
- **首现缩写注释**：行业缩写（IC/ASL/MTS/RAG/GTM 等）首次出现须注中文全称「中文全称（英文缩写）」；MCP/API/LLM/SaaS 等已普及缩写可免。自检新增「首现缩写注释」行。
- **多源合并稿（≥2 来源）**：走「通用模板 + **源口径标注** + **多源一致性核对**」；冲突须 `[编者注]` 并存或点明「**互补/不同维度**」，禁自称「互证」。详见 `references/interview-structures.md`「多源合并稿」。

## 对谈三层节结构（播客/访谈默认）

| 层级 | 作用 |
|------|------|
| **核心洞察** | 1–2 句结论，≤50 字 |
| **深度解析** | 衔接、背景、数字口径（分析师口吻）；讲者推理动作用引语保住，不改成编者转述 |
| **对谈实录** | 精编 `**全名**：「…」`；按语气迁移保留腔调、重复、反问与主持人问法；**非**字幕复读 |

- **默认启用**：Hard Fork、Lenny、Decoder、20VC 等多人 Q&A。
- **先定叙事轴**：若嘉宾在访谈中修正判断，按「旧判断→触发证据→实践/方案→个人行动」组织；每个 `##` 必须推进全文论点，相邻问答能无损合并时不得各立一节。
- **事实状态分离**：区分已发生、预测、目标、主持人口播与编者推断。用句末轻标记或节末一行「事实边界」，禁止写成「这不是……」式编者散文。
- **声纹卡必须写入自检**：每位核心人物 4–5 项特征，每项配一句成稿原句。遮名检验：实录前/中/后各抽 1 句，去掉姓名后仍能归属。精编不得统一改成分析师腔。
- **原声占比只作参考**：信息型约 35%，声口模式约 25%，争辩型约 50%。低于参考线在自检写原因，不阻断，也不得为贴近比例删原声。
- **标题承诺落地**：原标题的核心承诺若有素材支持，须进入正文 H1、全文论点或前段；若原标题夸张，则在导读说明边界，不得静默照抄成事实。
- **默认省略**篇末 `## 关键语录与交锋时刻`（金句已在各节实录）。
- **空壳实录**：无值得摘录的对话时**省略**整块 `### 对谈实录`，禁止留空标题（下游 `md2html-lecture` 亦支持缺省实录）。
- **用户可覆盖**：「不要对谈实录」「恢复关键语录节」「纯粹对话模式」等。

## 争辩型访谈 / 原声增强模式

- **触发条件**：分歧贯穿多个主题，出现连续追问、直接纠错、打断、拒答、要求保留/删去某段，或双方对事实与价值判断都不接受对方框架。单个尖锐问题、嘉宾批评第三方、多人各抒己见，**不自动触发**。
- **结构优先级**：保留冲突发生的时间顺序与升级过程；导读写 `> **核心冲突**：…`，不替素材制造单一「全文共识」。
- **每节顺序**：`### 原声交锋` → `### 语境与释义` → `### 未决问题`（确有悬而未决时才写）。编者解释置于人物声音之后，并明确事实、主张与推断的归属。
- **声纹卡**：动笔前记录句长、比喻、幽默、回避/反击与确定性强弱；成稿后写入自检并附证据句。删无信息填充，保留有意义的重复、自我修正、停顿、反问和节奏。
- **禁止假共识**：双方未达成共识时，不写「共识点」；争议信息用「A 主张…，B 质疑…，现场未解决…」。
- **适用边界**：只有局部交锋的普通访谈仍走三层结构，在对应小节加长实录、压缩解析即可；不要为一处反驳重排全文。

## 讲者 / 作者声口模式

单人演讲、主题演讲、作者长文（Substack、博客、专栏、通讯）**默认启用**。对谈三层与争辩型默认关闭；用户可显式开关。

- H1 优先沿用作者或讲者自己的核心表述，不另拟编者标题盖住原话。文件名仍按原标题信息。
- 深度解析允许较长引语，也允许整段保持讲者第一人称论证链。分析师句子只做衔接、背景和事实标记。
- 「不得用大段引语代替解析」**不约束**本模式：作者文字本身是内容。
- 第一人称链段首或段末用全名锚定一次，「我」属于讲者。

细则：`references/editorial-standards.md`「声口模式」；腔调：`references/language-and-gates.md`「语气迁移」。

## 核心导读（全文论点）

| 层级 | 作用 |
|------|------|
| **全文论点** | 导读首块 `> **全文论点**：…`，1–2 句合成中心主张 |
| **分层展开** | 2–4 短段，段首 `**{实质性标签}。**`，须覆盖目录末 2–3 节收束线 |
| **节级核心洞察** | 单节局部结论，≤50 字 |

## 加载策略

1. 先读本 `SKILL.md`，确认触发条件、交付物和红线。
2. 再读 `references/spec.md`（**参考集入口**：角色、偏好覆盖、决策流程图、执行步骤清单 + 分册路由表）。
3. 按素材与任务加载分册（路由表见 spec.md 顶部）：
   - **成稿与验收必读**：`references/language-and-gates.md`（三层分区、语气迁移、原声占比参考线、4c/4d、易错译法、可读性内化）+ `references/editorial-standards.md`（声口模式、事实状态标记、称谓、说话人对齐、防幻觉、元数据、术语校准）。
   - **播客/访谈/圆桌/多源素材**：加读 `references/interview-structures.md`（对谈三层、争辩型、多源合并、核心导读写法）。
   - **组装输出时**：加读 `references/templates.md`（文件命名 + 三个文档模板与自检表）。
   - **技术/Agent 工具向素材**：加读 `references/over-translation-guard.md`。
4. 4c 词库单源：`references/lexicon.txt`（`scripts/check_4c.py` 自动加载；手工 4c-1 grep 也以它为准）。
5. 金样（可选）：`fixtures/` 下迷你稿，用于核对结构与闸门，不必当正文素材。

## 链接类素材：浏览器优先（正文 + 元数据）

当用户提供了**可访问的主站 URL**，**默认先做浏览器抓取**（Cursor 内置浏览器 MCP：`browser_snapshot` / 滚动读全篇）。

**降级**：浏览器不可用、反爬、登录墙 → WebFetch → WebSearch（仅唯一对应本条时）→ 用户粘贴。须在自检注明 **主来源与降级原因**；**不要**在未尝试浏览器（或用户明示免浏览器 / 环境无浏览器 MCP）时假装已浏览器抓取。

## 角色与质量标准

你同时扮演**《连线》(Wired) 杂志的深度报道主笔**和**高阶知识萃取架构师**：信息无损、结构重组、信噪分离。**讲者或作者声音优先于编者声音**：比喻、幽默、锋芒、推理动作（举例、转折、先否定再给答案）留在原声或紧贴原话的引语里；分析师句子只做衔接、背景和口径。

成稿应达到：

- **信息覆盖抽样通过**（3 个互不重叠原文片段已落地或注明省略）
- **纯净深度文章感**（段内呼吸感 ≠ 节间多空行）
- **正文默认中文叙事** + **专名/技术概念标签不过译**
- **正文默认全名**指称人物

## 执行顺序

识别内容类型 → **判定对谈三层 vs 争辩型访谈 vs 通用模板（声口模式）vs 多源合并** → 超长则先分段预告 → 若有主 URL：浏览器优先（可降级）→ 元数据快照 → 术语校准与说话人对齐 → 主题/冲突弧重构 → 按模板成稿（解析与实录都走语气迁移）→ **语义保真闸门** → **`selfcheck.py`（4c+4d）** → 声纹附证据与遮名 3 句 → 信息覆盖抽样 → 自检报告。

## 交付物

- 默认目录：`output/`，除非用户指定其他位置。
- 文件名：`{发布日YYYYMMDD} {内容标题}_整理文档.md`；日期前缀必须来自内容发布时间。原标题含 `|` 时元数据表内写 `\|`（下游会还原），不改全角、不截断。
- 存量优化：最小 diff，见 `references/language-and-gates.md`「存量复审」。已有讲稿页 / 公众号稿的整理文档**改名或改内容后**，下游两份交付物要同茎重建（页脚、指纹、文件名都按源文件校验），见 `references/templates.md`「改名要传到下游」。

## 硬性红线

- **讲者或作者声音优先于编者声音**（不可覆盖）。用户可关实录、改体裁，不可把人物声音改成统一分析师腔。
- **防幻觉**；口播数字优先；术语校准；主持人引子入库；附着型信息过检。
- **排版纯净 + 4d**；**正文中文 + 4c**；**专名不过译**。腔调按语气迁移，不只查英文夹写。
- **对谈实录 / 原声交锋**：精编中文；与解析不得把同一事实讲两遍。推理链可以实录为主要归宿。争辩型保留追问、反击、回避与未决状态。
- **事实状态不可混写**：已发生、预测、目标、口播与编者推断用句末标记或节末「事实边界」标明；不得把时间表或愿景改写成已验证结果，也不得用编者否定句插入正文。

## 最低限度检查清单

- [ ] 已读 `references/spec.md`（入口）并按路由表加载了与素材类型匹配的分册（结构 / 闸门 / 模板）。
- [ ] 多人播客/访谈已判定「信息型三层」或「争辩型原声增强」，并在自检登记模式与依据。
