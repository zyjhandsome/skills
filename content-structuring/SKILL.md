# 内容结构化整理（Content Structuring）

## 你要做的事

把原始素材重构成一份读者**不必回到视频、播客或原文**也能掌握绝大多数关键信息的 Markdown 文档。你不是写读后感式摘要，而是做语义级的**全息降噪重构**：论点、数据、案例、步骤、推导、主持人追问、嘉宾语言风格和关键语录都要落地。

默认输出为中文，体裁是兼顾结构化与可读性的**深度文章版**。**多人播客、访谈、圆桌 Q&A** 默认采用「**对谈三层节结构**」：每节 **核心洞察 → 深度解析 → 对谈实录**（篇末省略独立关键语录节，金句沉入实录）。**成稿即中文**：叙述层与**对谈实录/关键语录**均直接用中文写；仅当用户显式要求「保留英文原文 / 中英双语」时才覆盖引语语言。用户可显式要求专栏文章模式、纯粹对话模式、不要对谈实录、简洁版等。

当用户**指定跨文化受众**（如「中国公民、赴美大一、熟悉课堂英文但不熟悉美国文化梗与高校语境」）或素材文化梗密集时，可启用**可选的「受众可读性内化适配」**：首次出现处补文化/人物/语境背景、客观第三人称口吻、**禁元叙述/禁「你们」说教/禁国内场景硬类比**，且**不降信息密度**——详见 spec「可读性内化适配（受众导向，可选）」。

## 默认中文化（必读摘要）

| 写什么 | 默认语言 |
|--------|----------|
| 导读、目录、正文、核心洞察、**对谈实录 / 关键语录** | **中文**（直接用中文写，禁止先英后译式夹写） |
| 公司/产品/API/**Agent Skill** 等专名 | **保留英文**（禁止过译，见下） |
| 元数据「原标题」、术语表专名列 | 可保留英文 |

**过译红线（v5.28）**：整理 Cursor / Claude / Agent 工具向素材时，**Skill / Agent Skill / Skill Creator / Hooks / Computer Use / Composer / Canvas / Subagent** 等是**产品专名**，保留英文；❌ 不要译成「技能 / 技能创建者 / 钩子 / 电脑使用」。人类软技能（沟通技能等）仍用中文「技能」。细则与更多专名：`references/over-translation-guard.md`。

**成稿后必做**：对叙述层与**对谈实录/关键语录**跑 spec **4c 检索** + **4c 验收闸门**（4c-1 词库 grep → 4c-2 连续英文通读 → 4c-3 对谈实录或关键语录独立扫）；**裸词**自检写 **grep 命中 X→修正后 Y**（首现 `中文（English）` 括注与专名白名单**不计入**失败）；并核过译护栏。**未过闸门不得标 ✅**。可辅以 `scripts/check_4c.py`。成稿后还须跑 **4d 节间空白验收闸门**（或 `scripts/normalize_spacing.py --check`），**未过不得标纯净排版 ✅**。优化存量 output 稿时：**最小 diff** 增量中文化，见 spec「默认中文化工作流」。

## 技术素材与多源合并（v5.27+）

- **AI/DevTools 行话**：整理 AI 编码、开发者工具类素材时，4c 须额外 grep「AI/DevTools 行话簇」。**判定原则**：产品/命令/协议/模型名（`Claude Code`、`MCP`、`/loop`、`worktree`、**`Skill`**）保留英文；**行为、状态、口语形容词**中文化，首现可「中文（English）」括注一次。
- **首现缩写注释**：行业缩写（IC/ASL/MTS/RAG/GTM 等）首次出现须注中文全称「中文全称（英文缩写）」；MCP/API/LLM/SaaS 等已普及缩写可免。自检新增「首现缩写注释」行。
- **多源合并稿（≥2 来源）**：走「通用模板 + **源口径标注** + **多源一致性核对**」；冲突须 `[编者注]` 并存或点明「**互补/不同维度**」，禁自称「互证」。详见 spec「多源合并稿」。

## 对谈三层节结构（播客/访谈默认，v5.23）

| 层级 | 作用 |
|------|------|
| **核心洞察** | 1–2 句结论，≤50 字 |
| **深度解析** | 论点、数字、因果、案例（分析师口吻） |
| **对谈实录** | 精编 `**全名**：「…」` 对话，保留幽默与张力；**非**字幕复读 |

- **默认启用**：Hard Fork、Lenny、Decoder、20VC 等多人 Q&A。
- **默认省略**篇末 `## 关键语录与交锋时刻`（金句已在各节实录）。
- **空壳实录**：无值得摘录的对话时**省略**整块 `### 对谈实录`，禁止留空标题（下游 `md2html-lecture` 亦支持缺省实录）。
- **用户可覆盖**：「不要对谈实录」「恢复关键语录节」「纯粹对话模式」等。

## 核心导读（全文论点，v5.26）

| 层级 | 作用 |
|------|------|
| **全文论点** | 导读首块 `> **全文论点**：…`，1–2 句合成中心主张 |
| **分层展开** | 2–4 短段，段首 `**{实质性标签}。**`，须覆盖目录末 2–3 节收束线 |
| **节级核心洞察** | 单节局部结论，≤50 字 |

## 加载策略

1. 先读本 `SKILL.md`，确认触发条件、交付物和红线。
2. 再读 `references/spec.md`（模板、闸门、词库、防幻觉的单一事实来源）。
3. 技术/Agent 工具向素材：加读 `references/over-translation-guard.md`。
4. 上下文紧张时，至少读 spec 中与素材类型相关的章节，以及：「执行决策流程图」「对谈三层节结构」「多源合并稿」「核心导读写法」「4d」「4c 验收闸门」「专名 vs 行话 / 过译」「防幻觉」「输出格式与文档模板」「执行步骤清单」。
5. 金样（可选）：`fixtures/` 下迷你稿，用于核对结构与闸门，不必当正文素材。

## 链接类素材：浏览器优先（正文 + 元数据）

当用户提供了**可访问的主站 URL**，**默认先做浏览器抓取**（Cursor 内置浏览器 MCP：`browser_snapshot` / 滚动读全篇）。

**降级**：浏览器不可用、反爬、登录墙 → WebFetch → WebSearch（仅唯一对应本条时）→ 用户粘贴。须在自检注明 **主来源与降级原因**；**不要**在未尝试浏览器（或用户明示免浏览器 / 环境无浏览器 MCP）时假装已浏览器抓取。

## 角色与质量标准

你同时扮演**《连线》(Wired) 杂志的深度报道主笔**和**高阶知识萃取架构师**：信息无损、结构重组、信噪分离，并保留发言人的比喻、幽默、锋芒和对谈张力。

成稿应达到：

- **≥95% 关键信息覆盖**
- **纯净深度文章感**（段内呼吸感 ≠ 节间多空行）
- **正文默认中文叙事** + **专名不过译**
- **正文默认全名**指称人物

## 执行顺序

识别内容类型 → **判定对谈三层 vs 通用模板 vs 多源合并** → 若有主 URL：浏览器优先（可降级）→ 元数据快照 → 术语校准与说话人对齐 → 主题重构 → 按模板成稿 → **4c（含过译护栏）** → **4d** → 自检报告。

## 交付物

- 默认目录：`output/`，除非用户指定其他位置。
- 文件名：`{发布日YYYYMMDD} {内容标题}_整理文档.md`；日期前缀必须来自内容发布时间。
- 存量优化：最小 diff，见 spec。

## 硬性红线

- **防幻觉**；口播数字优先；术语校准；主持人引子入库；附着型信息过检。
- **排版纯净 + 4d**；**正文中文 + 4c**；**专名不过译**。
- **对谈实录**：精编中文；与深度解析不得大段重复；无内容则省略空壳。

## 维护说明

`references/spec.md` 是**单一事实来源**。本 `SKILL.md` 为加载器与红线摘要。

1. 编辑 `references/spec.md`（及按需 `over-translation-guard.md`、`scripts/`）

3. 若使用 Codex 镜像目录，将本技能目录复制到 `~/.codex/skills/content-structuring/`（保持同 version）

**不再要求**维护已缺失的 `.cursor/rules/content-structuring.mdc` / `.codex/rules/...mdc` 四副本链；若将来恢复规则文件，须从 spec 生成且 version 一致。
