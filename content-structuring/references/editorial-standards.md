# 内容结构化整理 · 编辑标准、视觉保真、实操规范与抓取校准（参考分册）

> 本分册定义核心编辑原则、扫读呈现、**原文图与音视频三级视觉保真（纯远程外链协议）**、**实操演示规范**、声口模式、事实状态标记、全名与说话人对齐、定量口径防幻觉、多通道抓取链与元数据副表、以及术语校准。跨文件引用见 `SKILL.md`「加载策略」。

---

## 一、核心原则与扫读呈现

### 1. 核心编辑红线

1. **语义级无损**：核心论点、推导链、定量数据与口径、金句、案例细节与操作步骤完整落地，仅剔除无信息结巴与口头废话。
2. **洞察极简**：`### 核心洞察` 限 1–2 句纯中文结论，**≤50 字**，严禁堆砌长段或夹杂英文谓语串。
3. **短段落字数口径（废除模糊行数）**：常规叙述段建议 **100–200 字**，单段硬上限 **≤300 字**（由 4e-4 机检）；局部加粗核心数据、关键专名与精妙比喻，严禁用加粗英文动词顶替翻译。
4. **标题与分隔纯净**：正文 `##` 禁写 `1. ` / `1．` 序号前缀（顺序仅在 `## 目录` 有序列表体现；`12%`、`2012 年`、`66 岁` 等标题自有数字保留），严禁附加 `{#锚点}` 显式标签；正文各 `##` 节之间**严禁插入 `---`**，仅用一行空行分隔。
5. **捍卫人物风格与主客平衡**：讲者或作者声音优先于编者声音；多人对谈同步保留**主持人提问铺陈中的事实锚点**与**附着型偏好/时间预期句**（刻意省略须在自检注明理由）。括注 `[编者注：…]` 的原子块约束见 `language-and-gates.md`「4f 修订完整性」。

### 2. 扫读呈现与「解析层索引 vs 实录层展开」分工

按阅读阻力最小化选择形式：**短段落 → 段内分行 → 有序/无序列表或短语表格 → ≤6 节点 `mermaid` 小图**。因果推导与人物声口保持段落，不把整篇切成碎片幻灯片。

| 读者易卡壳处 | 扫读呈现方式 |
| :--- | :--- |
| 同一块介绍多位人物身份/经历 | `> **人物背景**` 内用空 `>` 行分段，**一人一段**；点到但未出场名单单独放末段；单主讲保持一段 `> **讲者背景**` |
| 并列步骤、多案例、多条件 | 有序或无序列表，列表前后保留一句衔接 |
| 双边/多边对照、圆桌立场坐标 | GFM 表格：**列数精简，单元格写约两行以内的紧凑短语**；更长的限定与解释挪到表下作完整句子（事实不删）。篇首元数据表、术语表、自检表不套两行限制 |
| 导读单个分层标签后并列 ≥3 件事 | 先写一句收束判断，再接短列表，禁串成文字墙 |
| 多分支/管道/状态流转文字难看清 | 放一张 **≤6 个节点**的中文 `mermaid` 流程图（仅呈现正文已写明的关系，不新增事实，也不替代原文配图） |
| 对谈三层中读者折叠实录快速扫读 | **深度解析承担「结构化框架索引」**：用紧凑对照表或步骤列表摆出本节核心维度与口径，让读者不展开折叠实录也能读懂骨架；**具体故事、追问交锋、比喻展开与推理原话归入 `### 对谈实录`**，避免第三人称散文复述（详见 `language-and-gates.md` 4e 规则） |

**对谈实录换气断段**：同一发言人长答在话题转换处新起一行 `**{全名}**：「…」`（定义、案例与下一论点不粘在同一对引号内），单段 ≤300 字。

## 二、原文图与音视频视觉保真（纯远程外链与内联重构协议）

> **全局铁律（零本地图片落盘）**：**严禁**在工作区或 `output/` 下创建 `assets/` 目录，**严禁**将任何图片或视频文件落盘保存到输出目录！整理文档中的所有配图一律只使用**源站/官方同源远程 URL（`https://...`）**或**内联结构化文本重构（`mermaid` / GFM 表 / 代码块）**。

### 1. 信噪比清点分类制（4 类必保真 vs 5 类必剔除）

摒弃不分青红皂白的机械全嵌或全丢，对网页正文图与音视频画面统一执行信噪比筛查：

- **✅ 4 类必保真高信噪比视觉项**：
  1. **定格数据图表 / 架构图 / 流程图 / Taxonomy 矩阵**（渐进翻页动画只取展开完毕的最终完整态）；
  2. **代码编辑器 / 终端输出 / 产品或 IDE 实操关键界面状态**；
  3. **白板推导 / 手绘草图完整态**；
  4. **实验结果 / 视觉效果 / 性能指标 A-B 对比画面**。
- **❌ 5 类必剔除视觉噪音（不入正文，记入自检剔除数并简述理由）**：
  1. Talking-head 单双人大头说话镜头、播客录音棚对坐、舞台远景；
  2. 纯章节大字标题页、议程目录页、致谢/二维码尾页；
  3. 纯装饰性 B-roll 空镜、无信息量的 AI 概念插画、纯情绪 Meme 或分割线小图标；
  4. 被播放器暂停按钮、进度条、弹幕或双层重叠字幕严重遮挡的污染画面；
  5. 讲者口播已 100% 逐字念完、无额外空间结构的三行纯文字 Bullet 页。

### 2. 网页文章源：远程原图直连与 URL 参数保护

- **标准语法**（图片与 `<video>` 均单独成段，空一行后**紧邻一行斜体中文图注**，中间禁插其它段落以确保下游 `md2html-lecture` 归入 `<figcaption>`）：

```markdown
![原文图 1：{结论式中文说明}](https://example.com/figure.png)

*原文图 1：{中文说明}（[原图地址](https://example.com/figure.png)）*
```

```html
<video src="https://example.com/figure.mp4" controls playsinline preload="metadata"></video>

*原文图 2：{动态演示说明}（[原视频地址](https://example.com/figure.mp4)）*
```

- **URL 参数保护规则（严禁盲删致 400/403）**：
  - **必须保留** X/Twitter 图床（`pbs.twimg.com/media/...?format=jpg&name=large`）的格式参数，以及飞书、语雀、Notion、Substack S3 等带鉴权或路由语义的查询参数（如 `?token=`、`?X-Amz-Signature=`）；
  - 仅在实测去掉参数后仍能正常直连加载原图时，才可移除纯尺寸缩放参数（如 `?w=640`）；URL 内严禁包含裸空格（下游 `md2html-lecture` 通过 `referrerpolicy="no-referrer"` 处理第三方防盗链）。
- **抓取完备性**：社交分享封面（`og:image`）与页眉 Banner 不得冒充正文图；若浏览器停在验证页或 `WebFetch` 仅返回一行 `Page image` 而漏掉正文 `<img>`，说明图片清单未完成，必须通过宿主浏览器渲染 DOM 提取真实图片 URL 后再成稿；确因权限无法打开时严禁编造 URL，在抓取降级与自检注明。

### 3. 音视频源：三级视觉保真协议（零本地图片文件残留）

整理 YouTube、Bilibili、视频播客、技术 Keynote 或实操录屏时，先扫描带时间轴字幕中的**视觉触发词**（`你看这张图 / 屏幕上 / 这行代码 / 架构图 / on this slide / as you can see / chart / demo`）及平台章节时间轴，对识别出的高信噪比视觉点按 **L1 → L2 → L3** 依次保真：

1. **L1 同源官方远程原图直连（优先）**：
   - 若同场官方配套发布博文、Release Note、Show Notes 或公开 Slide Deck 存在同源高清原图的公开有效 `https://...` URL，直接外链该远程地址，图注同时给出原图链接与原片定位时间戳：
   - `*原文图 N：{画面核心结论}（[原图地址](https://...) · 原片定位：[14:20](https://...)）*`
2. **L2 画面临时检视 / 口播完备 → 内联结构化重构（主力）**：
   - 若无公开同源原图 URL，可通过宿主浏览器定位视频画面，或用 `yt-dlp --download-sections "*HH:MM:SS-HH:MM:SS"` 配合 `ffmpeg` 在**系统临时目录**抽取定格帧完成读图（**提取完画面数据后必须立即删除系统临时目录中的切片与图片文件，严禁移入工作区或 `output/`**），或依据已完备的口播数据，将图表、架构、表格或终端代码无损重构为内联 ` ```mermaid `、GFM 对照表或代码块，并在紧随行标注溯源：
   - `*（据原片 [14:20](https://...) 画面/口播整理）*`
3. **L3 视觉盲区精确锚点（兜底）**：
   - 当无法获取视频画面且字幕缺失关键数值/符号时，**绝对禁止凭空猜测数据**，必须插入带精确时间戳与直达链接的盲区块：
   - `> ⚠️ **[视觉盲区 @ 14:20]**：{全名} 在此展示了 {图表/演示主题}，转写未包含具体读数（[直达原片 14:20](https://...)）。`

### 4. 嵌入位置、指代消解与 `| 原文图 |` 自检契约

- **嵌入位置硬约束**：所有 `![...](https://...)`、`<video>`、`mermaid` **只能放在 `### 深度解析`、`### 语境与释义` 或通用正文段落之间**（嵌在引入段之后、读数列表之前；多格图只在首次解读处嵌一次），**严禁插入 `### 对谈实录` 或 `### 原声交锋` 的对话轮次内部**（防止打断下游 `md2html-lecture` 时间线结构）。
- **正文指代消解**：严禁在正文留裸「如上图 / 见下图 / 看红框」，统一写为「**如图 N 所示，{核心结论与关键数值}**」，确保下游 `md2wechat` 听书场景不看图也能听懂。若原图标题含英文，中文 `alt` 先写中文结论，英文原题可置入 `（原片标题：…）` 括注。
- **自检统一登记**：在自检表 `| 原文图 |` 行如实登记（严禁仅写「无统计图」敷衍标 `✅`）：
  - 网页文章：`源页正文 N 张，稿内 N 张` 或 `候选 M 处：外链保留 K 张 + 剔除装饰噪音 D 处（附理由）`；
  - 音视频源：`关键画面 M 处：同源外链 K1 张 + 内联重构 K2 处 + 视觉盲区 K3 处`；
  - 纯音频播客：`不适用（纯音频源）`。

## 三、实操演示 / 教程 / Live Coding 视频保真规范

当素材为软件/AI 工具实操录屏（如 Cursor / Claude Code 工作流演示）、编码教程、技术 Workshop 或配置演练时，不能只写宏观感悟，必须在对应章节 `### 深度解析` 按**四步结构**落地可复现操作链：

1. **前置环境与版本卡**：在首节或环境节集中列出工具/模型版本、操作系统、依赖包、开启的实验性开关或前置目录结构（原片未提项不编造）。
2. **单步四要素闭环**：每个核心实操动作按 **「步骤目标 → 精确输入（代码块 / CLI 命令与参数 / 配置文件键值 / 可执行英文 Prompt 原文块）→ 屏幕状态变化或预期输出 → 讲者点明的踩坑与排错提示」** 完整呈现。
3. **口播现场指代强制消解【红线】**：严禁在成稿中残留「点这里」「把这个参数改成这样」「像屏幕上这样写」「切回刚才那个窗口」等未消解指示词——必须结合上下文或画面检视还原为明确的 UI 路径、命令标志、文件名或变量名；纯文本转写确实无法还原时，按上节 L3 标 `[视觉盲区 @ MM:SS]`。
4. **可执行英文 Prompt 保真**：演示中用于驱动模型的英文 System Prompt、Skill 片段或指令模板，必须原样放入代码围栏/引用块供读者直接复制（外围配中文拆解），禁止意译成无法直接执行的中文散文。

## 四、讲者 / 作者声口模式

- **默认开关**：单人演讲、Keynote、作者长文（Substack、博客、专栏、通讯）**默认启用**；多人对谈三层与争辩型默认关闭（用户可显式开关，但「人物声音优先」底线不可关）。
- **执行细则**：
  1. **正文 H1**：优先沿用讲者/作者自己的核心表述或有原文支撑的原标题骨架（译为自然中文），不另起一套编者总结式标题盖住原话；与 `{内容标题}` 同义时文件名按 `templates.md` 省略短标题。
  2. **第一人称论证链与长引语**：`### 深度解析` 允许较长直接引语或整段保持讲者第一人称论证链（「我」归属讲者，段首或段末用**全名**锚定一次）；分析师句子只做章节衔接、背景补注与事实状态标记。
  3. **保留原有推理次序与收尾力度**：先否定再给答案的保持原先后次序，段尾保留讲者自己的判断句或冷幽默，不用编者总结句抹平。
  4. **默认省略篇末语录节**：启用声口模式时，精彩原话已在各节解析中呈现，**默认省略**篇末 `## 关键语录与交锋时刻`（用户显式要求保留除外）。

## 五、事实状态标记、全名指称与说话人对齐

### 1. 事实状态轻标记与事实边界

区分「已核实事实」与「预测/目标/口播/推断」，严禁用「这不是……」「这是修辞，不是……」等编者否定散文插入正文：

- **句末全角方括号轻标记**（置于句号前）：`［预测］`（未发生的时间表/估计）、`［目标］`（希望达到/试点中/认证中）、`［主持人口播］`（主持设定且嘉宾未当场确认）、`［编者推断］`（必要逻辑补步）、`［口播修辞］`（夸张枚举而非精确清点）。讲者原句已含「预计 / 大概 / 我认为」自我限定时，保留原词即可，不必叠床架屋再加标记。
- **节末事实边界块**：若单节需标记处密集影响阅读，改为在该节解析末尾集中写 1–2 行：`> **事实边界**：{说明哪项数字属预测或口播口径}。` 全篇带 `事实边界` 的节占比 **≤60%**（4e-5），只标真正易被误读为既成事实的硬指标或绝对化断言。

### 2. 称谓与署名（正文默认全名）

- **篇首元数据区**：表格左列保持 **`讲者` / `对谈人物`** 等标准栏名；背景块保持 `> **讲者背景**`（单人）或 `> **人物背景**`（多人分行）。
- **正文、洞察、列表与语录署名**：默认一律使用**人物全名**（如 *Greg Brockman*、*Alex Kantrowitz* 或已确立中文全名），严禁用 `讲者`、`对方`、`此君`、无前文锚定的孤立 `他/她`，或仅写单姓/昵称（用户显式指定简称模式除外）；同段首句写全名后，紧邻一两句可用 `他/她` 自然承接；外语原话引语内的直呼保留原貌。

### 3. 说话人角色对齐、引子入库与 `[说话人待核]` 红线

- **二次逻辑对齐**：根据提问语气、立场连贯性与专业视角主动修正 ASR 主客串音。
- **存疑诚实标注【防伪造归属】**：多人圆桌或嘈杂音频中，若经上下文推理仍无法唯一确认某句关键发言归属谁，**严禁强行猜一个人名挂上去**，必须写为 `**[说话人待核：疑似 {全名 A} 或 {全名 B}]**：「…」` 并在自检「术语校验」行说明。
- **主持人引子入库 & 附着型信息过检**：主持人提问前给出的产品代际、对比设定或背景数字（嘉宾未否定时）须至少一句承接进解析或实录；讲者顺口提及的「个人最爱/偏好」「带具体时间窗的预期」「半开玩笑的立场修饰」成稿前逐一过检，不入正文须在自检写明省略理由。

## 六、定量口径保真、防幻觉与原数据抓取规范

### 1. 防幻觉与定量指标「口径四要素」规范

1. **视觉盲区三阶处理**：严禁对未见图表捏造数值，严格执行本分册第二节「L1 同源外链 → L2 临时检视/口播重构 → L3 `[视觉盲区 @ MM:SS]` 直达锚点」。
2. **ASR 不确定性标注**：漏字、半截数字或否定词可疑时严禁脑补，标 `[ASR不确定 @ MM:SS：…]`（无时间轴省去 `@ MM:SS`）；原文「大约 / 可能」等模糊限定词必须保留。
3. **口播数字优先与双口径说明**：正文优先采用逐字稿口播数字；若同时引用官方新闻稿/Banner 的不同数值，用 `[编者注：口播约 X；官方页面披露为 Y]` 并列说明，严禁静默改数。
4. **定量指标「口径四要素」绑定保真【防裸数失真】**：凡涉及增长率、留存率、延迟、推理成本降幅、准确率、营收/ARR、样本规模等核心数字，必须将原文已给出的 **① 指标定义与分母范围、② 统计时间窗口、③ 对照基准（Baseline，如 P50 vs P99、毛利 vs 净利、对比哪一代模型）、④ 数据状态（实测/口播估算/目标预测）** 与数字同行绑定保留！严禁在 4e 压缩解析时只留裸数字而切丢口径限定（原片未交代某要素时保持原貌，不自行补全）。
5. **多源一致性核对（≥2 来源必做）**：跨源同一指标或枚举冲突时严禁折中取均值或默认取大数，必须用 `[编者注：A 源称…，B 源称…，统计窗口分别为…]` 并存，或点明「**互补 / 不同维度**」（严禁自称「互证」），并在自检「多源一致性」行登记冲突项数。
6. **发布日期、播放量与总时长精确核验**：相对发布时间（如「3 天前」）须基于当前权威日期推算并注明；播放量/访问量写明平台口径（未获取写 `未获取（原因）`，禁估算）；音视频总时长统一写 `HH:MM:SS`（纯本地字幕用首末条推算并注明 `由字幕末条推算`，纯文稿填 `不适用（文稿）`）。

### 2. 多通道抓取降级链与元数据副表契约

- **抓取优先级**：
  1. **协同第一优先（宿主浏览器 + `agent-reach`）**：对网页长文、X Article/帖子、Substack、Medium、博客等，优先用**宿主可用浏览器工具**（如 Cursor Browser、Orca Browser 等）滚动加载完整正文、提取渲染态 DOM 原图远程 URL 与链上实时播放/阅读指标；对 YouTube、Bilibili、Twitter/X 线程、小红书、小宇宙播客等平台链接，协同优先使用 **`agent-reach`**（`subtitle / transcribe / read / thread`）拉取完整带时间轴字幕轨与原始元数据。
  2. **降级链**：`WebFetch`（静态公开 HTML；若仅得 `Page image` 须补抓 DOM 原图）→ `WebSearch`（仅当片段唯一对应本条内容时补证）→ 用户粘贴全文/本地导出字幕。自检与元数据「内容来源」如实写明主通道与降级原因，未用浏览器时严禁伪称浏览器抓取。
- **元数据副表契约（严禁新增顶层 `## 提及资源` 节）**：
  - **`### 官方章节索引`**：音视频含平台章节或清晰时间段时，置于 `## 文章元数据` 主表下方、`> **人物/讲者背景**` 上方，供读者按时间定位且被 `md2html-lecture` 原生保留。
  - **`### 核心引用与资源`**：正文或播客 Show Notes / 简介栏中讲者重点讨论且给出真实 URL 的论文（如 arXiv）、开源仓库、基准报告与核心工具，在正文首次提及处加行内 Markdown 链接，并可汇总为 `## 文章元数据` 下的 `### 核心引用与资源` 副表（严禁猜测或编造未出现的 URL；严禁写成顶层 `##` 节以免破坏 4d 分隔线门禁与下游公众号章节映射）。
