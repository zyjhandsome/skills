# 内容结构化整理 · 访谈、圆桌、混合演讲结构与核心导读（参考分册）

> 本分册定义对谈三层节结构、争辩型访谈/原声增强模式、**单人 Keynote + 尾声 Q&A 混合路由**、**≥4 人圆桌（Panel）声纹与多边光谱**、说话人时间角注契约、多源合并稿以及核心导读写法。语气迁移与 4c–4f 闸门见 `language-and-gates.md`；视觉保真与事实标记见 `editorial-standards.md`；统一文档外壳见 `templates.md`。

---

## 一、对谈三层节结构（洞察 → 解析 → 实录）

**适用场景**：信息型多人播客、访谈、圆桌、现场 Q&A（如 Hard Fork、Lenny、Decoder、20VC 等默认启用）。读者可先通过解析层的结构化索引快速掌握全局骨架，再展开实录体验现场交锋与人物声口，无需回听原音频。

### 1. 先定叙事轴，再定章节

- **立场演化轴合并**：若嘉宾在访谈中呈现「旧判断 → 触发证据 → 新判断 → 组织/制度实践 → 个人行动」的观念演进，仍采用对谈三层，但按该演化轴合并相邻追问，严禁一问一节机械切碎。
- **章节推进测试**：每个 `##` 必须推进读者对全文论点的认知；相邻问答属于同一因果链且合并无损时必须合并（单节超过 3500 字触发 4e-3 时再按子论点拆分）。
- **现场零散问答归位**：观众或主持人的零散提问优先归入主体对应主题节；确有独立新论点的提问才单独成节，**严禁把不相关问答堆成篇末「杂项 Q&A」节**。

### 2. 每节固定三层与硬规则（顺序不可颠倒）

节内骨架见 `templates.md`「插槽 A」（`## {实质性节标题}` → `### 核心洞察` → `### 深度解析` → `### 对谈实录`）：

1. **禁节下过渡段**：`##` 与首个 `### 核心洞察` 之间仅留一行空行，禁止在 `### 核心洞察` 前插入过渡叙述。
2. **解析层框架索引 vs 实录层现场展开**：
   - `### 深度解析`：用分析师口吻交代背景、因果衔接与数字口径四要素，并用紧凑短语对照表或步骤列表搭好本节框架索引（保证读者折叠实录也能扫读完本节骨架）；远程原图/`<video>`/`mermaid` **仅嵌在本层段落之间**。
   - `### 对谈实录`：精编 `**{全名}**：「…」`，保留问答顺序、追问锋芒、自我修正、有意义的重复、反问与幽默（非字幕复读）；讲者的关键推理链与鲜活故事以实录为主要归宿，两层不把同一事实完整讲两遍（4e-1/4e-2 机检）。**严禁在实录对话轮次内部穿插图片、`<video>` 或流程图**。
3. **对话轮次时间戳与跨时段合并角注【跨端正则契约】**：
   - 当输入源含时间轴时，在每节实录首轮、关键转折点或按立场演化轴**跨时段合并**处，统一采用说话人角注格式：`**{全名}**（14:20）：「…」` 或 `**{全名}**（14:20, 58:10 合并）：「…」`。
   - **严禁**把时间戳写进 `##` 节标题（防污染下游公众号 H2），也**严禁**在实录轮次间单独起行裸写 `[14:20]`（防下游 `md2html-lecture` 时间线拆裂；`md2wechat` 听书模式会自动剥离该角注）。
4. **换气断段与字数口径**：每次换说话人必写 `**{全名}**`；一人长答在话题转换处断成多段 `**{全名}**：「…」`，单段 **≤300 字**（4e-4）。
5. **空壳实录省略**：某节若无值得单独摘录的对话张力（核心原话已入解析引语），**整块省略 `### 对谈实录`** 并在自检「节结构」行注明省略节数，严禁留空标题壳。
6. **默认省略篇末关键语录节**：精彩表达已沉入各节实录，默认省略 `## 关键语录与交锋时刻`（用户显式要求保留时仅收跨节核心金句，禁与实录大段重复）。
7. **与「纯粹对话模式」区分**：用户显式指定「纯粹对话模式」时，按 `spec.md` 豁免矩阵每节仅保留 `### 核心洞察` + `### 对谈实录`（省略 `### 深度解析`），既保住 4d-3 首层结构又让对话成为全文主体。

## 二、争辩型访谈 / 原声增强模式

**适用场景**：分歧贯穿多个主题，让读者看清问题如何被逼问、回答如何回避或反击、哪句触发升级、哪些分歧最终悬而未决，而非替双方捏造共识。

### 1. 触发判定（至少满足两类信号，且跨越多个主题）

| 信号类别 | 典型现场表现 |
| :--- | :--- |
| **连续追问** | 同一问题换角度反复追问；嘉宾回答未回应主持核心设问 |
| **直接纠错** | 「不对」「完全错误」「你曲解了我的意思」等正面否定对方事实框架 |
| **现场控制** | 频繁打断、拒绝回答、要求保留/删去某段、反问主持人立场动机 |
| **立场升级** | 从具体事实分歧升级至制度合法性、道德责任或权力归属对抗 |
| **无共识收束** | 收尾仍明确「我不同意」，或仅承认分歧本身存在 |

*注：嘉宾批评未到场第三方、单次尖锐提问后恢复常规访谈、多人各抒己见无追问链，均**不触发**本模式（仍走对谈三层，在对应小节加长实录即可）。*

### 2. 组织原则与节内顺序

节内骨架见 `templates.md`「插槽 B」（`### 原声交锋` → `### 语境与释义` → `### 未决问题`）：

1. **保留冲突升级弧线**：按现场交锋发生与升级的时间顺序组织，导读首块写 `> **核心冲突**：…`（写清双方不同标尺，不裁定胜负）。
2. **先声后解**：先完整呈现一轮原声攻防（可带 `**{全名}**（08:15）：「…」` 时间角注），再在 `### 语境与释义` 补充读者无法从对话直接获知的背景、定量口径与认识边界（配图仅放本层）。
3. **归属明确与严禁假共识**：争议判断写清「A 主张…，B 质疑…，现场未给出…证据」；引号外的正文或自检通过项出现无否定的「共识点 / 达成共识 / 双方一致 / 全文共识」时，`check_judgment.py` 将在争辩型模式下直接报错退出 1。
4. **未决问题按需保留**：仅当该节确有现场未化解的实质冲突时保留 `### 未决问题`，否则省略。

## 三、单人 Keynote + 尾声 Q&A 混合体裁与 ≥4 人圆桌规范

### 1. 「前单人演讲 Keynote + 后现场 Q&A」混合路由

针对技术发布会、学术报告、公开课常见的「前段单人主讲 + 尾声主持/观众问答」混合形态，严禁二元一刀切或把问答堆成篇末杂项节：

- **主讲章节**：采用通用模板（`### 核心洞察` + `### 深度解析`）并**默认启用声口模式**（H1 沿用讲者核心表述，解析保留第一人称论证链，默认省略篇末 `## 关键语录与交锋时刻`）。
- **尾声 Q&A 归位**：
  - 若提问紧扣前文某一主讲章节的论点或数据，直接并入该主讲章节末尾，追加一块 `### 对谈实录` 呈现问答交锋（下游 `md2html-lecture` 原生支持同篇内部分节无实录、部分节含实录混排）；
  - 若提问开辟了主讲未涉及的独立新主题（如架构演讲后追问商业定价或开源协议），则单独新开标准对谈三层节。

### 2. 多人圆桌（≥4 位出场人物 / Panel）声纹、光谱与归属规范

当播客或圆桌出场人物 **≥4 人**（如 1 主持 + 3～5 位嘉宾，或 4 人常驻圆桌）时，叠加以下三条降噪与保真规则：

1. **多边立场光谱表**：当三位及以上嘉宾对同一议题给出不同判断或限定条件时，在该节 `### 深度解析` 先用一张紧凑短语对照表锚定各人立场坐标（支持 / 附条件支持 / 质疑 / 关注切面），再进入 `### 对谈实录`。
2. **声纹卡主次分级（防自检膨胀）**：不再机械给每个人列满 5 条——**核心主发言人（1–3 人）每人列 3–4 项特征 + 成稿原句，次要发言人每人列 1–2 项最具辨识度特征 + 成稿原句**；遮名检验抽取最易混淆的 3–4 句覆盖不同核心人物。
3. **串音存疑诚实标注**：多人抢话或声线接近导致上下文仍无法 100% 锁定发言人时，标 `**[说话人待核：疑似 {全名 A} 或 {全名 B}]**：「…」`，严禁强行指认造假。

## 四、人物声纹与遮名检验交卷规范

声纹必须在文末 `## 自检报告` 实证交卷（供 `check_judgment.py` 核验原句真实性）：

1. **`### 人物声纹（附证据）`**：每位核心人物（常规双人访谈每人 4–5 项；≥4 人圆桌按上节主次分级）记录句长节奏、高频比喻、幽默/反讽方式、确定性强弱或应对追问动作，**每项配一句成稿正文中可精确检索到的原句**。
2. **`### 遮名检验`**：从正文**前、中、后**各抽 1 句（**严禁复读上方声纹已引用的证据句，且 3 句互不重复**），隐去姓名写成 `1. 「{去姓名原句}」→ {全名}`：
   - **多人稿**：检验去掉姓名后至少 2/3 能否凭语气与立场准确归属对应人物；
   - **单人声口稿**：同样采用 `1. 「{去姓名原句}」→ {讲者全名}（声口印记：{具体口吻特征}）` 格式（兼容 `check_judgment.py` 语法），检验该句是否保留了讲者独有声口而非通用编者腔；若三句皆像千篇一律的分析师总结，须退回重修精编。

## 五、多源合并稿（≥2 来源合成）

合并同一主题的多条视频、播客与深度文时，以公共外壳 + 通用模板为基底叠加四条规则：

1. **源口径显式标注**：关键数字、时间线与判断在正文标明来源口径（如「**@Scale 演讲口径** 单日 150 PR」「**Platformer 专访口径** 20–30 PR」）。
2. **冲突口径并存（禁伪称互证）**：跨源数字或枚举不一致时，按 `editorial-standards.md` 用 `[编者注：A 源称…，B 源称…，窗口分别为…]` 并存，或点明「**互补 / 不同维度**」，严禁私自折中或自称「互证」。
3. **按需局部内嵌实录**：来自播客/访谈的章节可在节末内嵌精选 `### 对谈实录`，纯文稿来源章节仅保留 `### 核心洞察` + `### 深度解析`。
4. **元数据与自检闭环**：元数据表启用 `| **关联素材** |` 列出全部合并来源（名称 + URL + 定位），延伸引用汇总入 `### 核心引用与资源` 副表；自检「节结构」填 `多源合并（通用模板+内嵌实录）`，「多源一致性」登记 N 链覆盖与冲突处理项数。

## 六、核心导读写法（全文论点 / 核心冲突）

`## 核心导读` 是全篇的论证脊梁，让读者只读导读即可把握中心论断或核心争议轴，绝非「先谈了 A、又聊了 B」的流水账回顾。

| 导读层级 | 写法与功能 | 篇幅约束 |
| :--- | :--- | :--- |
| **首块：全文论点 / 核心冲突** | 常规稿写 `> **全文论点**：…`（1–2 句可证伪中心主张，呼应标题核心隐喻）；争辩型写 `> **核心冲突**：…`（点明双方标尺差异与不可调和处） | 1–2 句引用块 |
| **主体：分层展开** | 按内在逻辑弧线设 2–4 段，段首用 `**{实质性标签}。**`（如 `**架构转向。**` `**商业化边界。**`，禁写「第一部分」）；标签后并列 ≥3 项时用一句收束 + 短列表 | 2–4 段（简洁版 1–2 段） |
| **收束线强制覆盖** | 落笔前对照目录**末 2–3 节**，确保后半场关键收束论断（治理、风险、行动路线等）在导读末段显式覆盖，严禁「半程导读」 | 覆盖全文首尾 |
| **原标题承诺校验** | 原标题的核心看点或数据承诺若有原文支撑，须在 H1、全文论点或首段显式兑现；若原标题系夸张标题党，须在导读点明实际证据边界 | 防标题落空 |
