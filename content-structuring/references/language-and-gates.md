# 内容结构化整理 · 语言分区与 4c/4d 验收闸门

> 成稿与验收必读（v5.38）。词库在 `lexicon.txt`，过译黑名单在 `over-translation-guard.md`。语气迁移与原声占比见下文；声口模式与事实状态标记见 `editorial-standards.md`。

默认交付物是**中文深度文章**，不是「中文骨架 + 英文转写夹写」。高保真指论点、数字、步骤、案例、比喻与张力不丢，**不等于**叙述句里留英文原词。

## 三层语言分区

| 层级 | 范围 | 语言 |
| :--- | :--- | :--- |
| **叙述层** | 导读、目录、正文、列表、Q&A 归纳、**核心洞察、对谈实录 / 原声交锋 / 关键语录** | 中文写清含义 |
| **专名 / 术语保真层** | 公司/产品/模型/API、已校准术语、行业缩写，以及讲者用作角色/范式/工作流原语/对照组的标签 | 保留通行英文；首次可中英并写。行业缩写首现注「中文全称（英文缩写）」；MCP/API/LLM/SaaS 可免 |
| **档案层** | 元数据「原标题」、术语表专名列、ASR 音译 | 可留原文。语录**不在**此层 |

**译中文**：通用动作/状态/形容词（*fully auditable*、*actionable*、*dogfooding*），以及不当标签用的名词短语（*outcome spec* → 产出规格）。**留英文**：品牌与产品名、API/协议/UI 字段、概念标签（**Builder / Agent Loop / Loop / Graph / Harness / Evals** 等）；taxonomy 整组保留。ASR 听不清写 `[ASR不确定]`，不要用英文假装更忠实。

### 概念标签四问

1. 产品、UI、命令、代码对象或文件名？→ 留英文。
2. 讲者在命名概念、身份、范式或演化链？→ 留英文标签，首次可释义。
3. 中文译不出可检索性或圈内指向？→ 「中文说明（English）」或留英文。
4. 以上都不是 → 译成自然中文。

❌ `先是代理，然后循环，然后图` → ✅ `先是 Agent，接着是 Loop，再到 Graph`  
❌ 为过 4c 把 **Agent Loop / Harness** 全译没 → 先判指称。  
标签首次解释一次即可；不要整句恢复英文。

口播 coined term 首次 **中文（English）**，后文中文。目录标题默认中文。加粗中文结论、数字、专名、比喻，不要加粗英文动词顶替翻译。腔调按下文「语气迁移」用中文重现，不要收成统一书面腔。用户要求「保留英文原文 / 中英双语」时覆盖语录语言，须在自检注明；双语固定为中文主句 + `（原文："…"）` 或并列块。

## 常见失败模式

| 失败 | 反例 | 改法 |
| :--- | :--- | :--- |
| 加粗英文顶替翻译 | `**operationalize**` | 「**落地执行**」 |
| 核心洞察英文化 | `> **Dan Shipper super bullish…**` | 洞察全中文；原话进实录/语录 |
| 半句夹写 | `重组有，**mass unemployment** 无` | 「不会出现**大规模失业**」 |
| coined term 当正文主体 | 反复 `ride the models` | 首次括注，后文中文 |
| 括注式夹写 | `great products（伟大产品）` | 正文写中文 |
| 误标自检 / 排版 | 未跑机检却 ✅ | 先跑 `selfcheck.py` |
| 呼吸感误读 | 节间多空行或 `---` | 段内短段落；节间单空行 |
| 高保真误读 | 堆 `refine`，或把 **Builder** 译没 | 普通义中文；标签按四问 |

## 硬分层

- **核心洞察**：1–2 句纯中文，≤50 字；禁止英文谓语串。洞察是结论，不是把讲者口吻改写成编者判断。
- **深度解析**：衔接、背景、数字口径用分析师口吻，通常 200–400 字，不超过同节实录的一半（4e-2）。解析回答「这段对话为什么重要、在全文里处在什么位置、哪些数字要怎么读」，不复述实录里的故事、数字和原话。把几句「他说……他认为……」合成一句带因果的中文，避免逐句转述造成的翻译腔。讲者怎么举例、怎么转折，交给实录；解析里确需引语时最多 1–2 句。声口模式不受「短引语」约束，见 `editorial-standards.md`。
- **对谈实录 / 原声交锋**：精编 `**全名**：「…」`，默认中文；按「语气迁移」保留腔调。主持人的追问、玩笑、自嘲与嘉宾同一标准。非字幕复读。一人长答在话题转换处断成多段，每段一个说话人标签，单段 ≤300 字（4e-4）。
- **篇末关键语录**：仅通用模板默认保留；对谈三层默认省略。
- **事实状态**：句末 `［预测］` `［目标］` `［主持人口播］` `［编者推断］` `［口播修辞］`，或节末一行 `> **事实边界**：`。禁止「这不是……」「这是修辞，不是……」。用法见 `editorial-standards.md`「事实状态标记」。

## 语气迁移（实录、解析引语、声口论证链）

适用于 `### 对谈实录`、`### 原声交锋`、深度解析中的引语，以及声口模式下的第一人称论证链。目标是中文读者能听出这个人怎么说话。讲者或作者声音优先于编者声音。

### 可删与必须保留

| 处理 | 内容 |
| :--- | :--- |
| **删** | 无信息结巴；重复启动词（就是就是、嗯嗯）；不改变态度的填充（you know / I mean） |
| **留** | 自我修正；有意义的重复；反问；半句打断；语气词（真的、对吧、听着）；先否定再给答案；举例时的口吻 |

划界：删掉后意思与态度都不变 → 删。删掉后少了犹豫、强调、反讽或权力关系 → 留。拿不准时留。

### 语域

- 口语对齐本人：短句的人不要连成复合长句；爱铺陈的人不要切成电报体。
- 句长：精编后的中文单句贴近原句的信息步长。不要把三句口头判断合成一句编者判断。
- 反问仍是反问，祈使仍是祈使。
- 语气词每段留 1 处能代表此人的即可，不要逐个 um 对译。
- 允许少量舞台提示：`（笑）` `（停顿）` `（被打断）`。只标会改变理解的瞬间。

### 俚语、双关、标志性表达

- 俚语和双关先译意，紧跟短注：`（原梗：…）`。注只解释梗，不评价对错。
- 同一口号、自造搭配或反复出现的判断句，全文只用一个译法。动笔时列 3–8 条「原文 → 固定中文」，写入自检声纹备注。后文不得另译。

### 两层怎么用

- **实录 / 原声交锋**：整段按本指南精编。主持人提问风格（追问、玩笑、自嘲）与嘉宾同一标准，不得只留事实引子。
- **深度解析**：衔接和口径仍是分析师句子。一旦进入讲者怎么推理，改用引语或声口链，并套用本指南。禁止用「这不是……」把编者判断写成正文主句。
- **声口模式**：第一人称论证链整段适用本指南；「我」是讲者，段首或段末用全名锚定一次。

## 原声占比参考线（提示，不阻断）

原声 = 实录 / 原声交锋的字数，加上解析层里的直接引语，以及声口模式的第一人称论证链。分母 = 原声 + 深度解析（或语境与释义）的叙述句。不含导读、目录、元数据、自检。

| 模式 | 参考线 | 含义 |
| :--- | :--- | :--- |
| 信息型对谈三层 | 约 35% | 实录加解析中的引语 |
| 单人演讲 / 作者长文（声口模式） | 约 25% | 引语加第一人称论证链 |
| 争辩型 | 约 50% | 原声交锋为主 |

参考线是**下限提示，不是上限，也不是通过条件**。低于参考线时自检写估算和原因（例如第二来源是机译、某节无张力已省略实录）。不得为了贴近比例删原声。解析若被引语挤到缺背景，把背景补回解析，不要删原声。

## 4c / 4d 验收闸门

成稿后先跑 `python scripts/selfcheck.py {稿}`。**未跑机检不得**把「正文中文叙事」「纯净排版」标 ✅。

**扫**：导读、目录、解析、洞察、实录 / 原声 / 语录。**不扫**：原标题、术语表专名列、「原文：…」副行、代码块、链接。

| 步骤 | 机检 | 通过 |
| :--- | :--- | :--- |
| **4c-1** | `ACTIONABLE_HITS` | 裸露通用夹写 = 0。括注与 `[allow]` / `[allow-case-sensitive]` 不计；小写 `builder` / `agent loop` 不豁免 |
| **4c-2** | `CONSECUTIVE_ENGLISH_4C2` | 每条译中文或确认为专名。未核实不得 ✅。默认不因此退出 1 |
| **4c-3** | 人工扫实录 / 原声 / 语录 | 无英文半句（专名除外） |
| **4d-1** | `---` 计数 | ≤6，且只在元数据/导读/目录后、语录（通用模板）/术语表/自检前；正文节间 0 |
| **4d-2** | 三连空行 | 0 |
| **4d-3** | `##`→首个 `###` | 恰好 1 空行（对谈三层必须是核心洞察） |

## 4e 可读性闸门（v5.37）

`selfcheck.py` 同时输出「可读性机检」行（脚本 `check_readability.py`）。只扫带 `### 深度解析` / `### 语境与释义` 的正文节。4e 是警告，不让进程退出 1；但标 ✅ 前必须逐条改掉，或在备注写出不改的理由。

| 步骤 | 机检 | 阈值 | 改法 |
| :--- | :--- | :--- | :--- |
| **4e-1** | 解析与实录 8 字片段重合 | ≤20% | 解析删掉实录里已有的数字、案例与原话复述 |
| **4e-2** | 解析篇幅 | ≤ 同节实录的一半（最少允许 450 字） | 解析只留背景、口径、因果衔接，通常 200–400 字；删掉的独有事实移进实录（见 4f） |
| **4e-3** | 单节总长 | ≤3500 字 | 拆节，或把旁支问答并入所属主题节 |
| **4e-4** | 长段落 | 单段 ≤300 字 | 实录在话题转换处断段，同一说话人可连续多段 |
| **4e-5** | 事实边界密度 | ≤60% 的节 | 只给读者会误当成已核实结果的句子加边界 |

**为什么需要 4e**：三层结构最常见的失败，是解析把实录换成第三人称再讲一遍，读者读了两遍同样的事。原声占比参考线只能靠实录达标，不能靠解析复述达标。重合度按字面计算，意译复述测不出来，所以 4e-2 的篇幅比例同样要守。段长合格仍可能不好扫：多人、步骤、对照挤在一段时，按 `editorial-standards.md`「扫读呈现」换行、列表、表格或图。

## 4f 修订完整性：压缩不等于删除（v5.38）

4e 会推着解析变短。变短只在一个前提下安全：被删的内容，实录里本来就有。解析里独有的事实、例子、限定句，必须**移进实录**（放回讲者原话），不能随解析一起删掉。可读性修订不得降低信息量。

**每次压缩、拆节、重写已有稿之前**：先把修订前的稿子另存一份（临时目录即可）。改完后运行：

```bash
python scripts/selfcheck.py 修订后.md --before 修订前.md
```

脚本输出「修订完整性」行和两份清单：

| 步骤 | 内容 | 处理 |
| :--- | :--- | :--- |
| **4f-1** | 修订前有、修订后没有的数字与英文专名 | 逐项补回，或说明去向（如 ASR 纠错移入自检、误写已更正） |
| **4f-2** | 修订后找不到对应表述的句子，按保留比例从低到高排序 | 从上往下读，直到剩下的都只是换了说法；真丢失的补回实录 |

4f-2 按字面匹配，意译也会出现在清单里，所以它是复核队列，不是判定。自检「修订完整性」行必须列出补回了哪些内容、哪些是刻意删除及理由；没跑 `--before` 比对的修订稿，这一行不得标 ✅。

`CONTEXTUAL` / `OVER_TRANSLATION` 须对照来源，不是机械替换。`lexicon.txt` 是词表单源；新词只加那里。`[blocking]` 里的词（`refine`、`holistic`、`vibe`、`persona`…）不是专名。

自检「正文中文叙事」先贴 `selfcheck.py` 行。新建稿写 4c-1 X→Y、4c-2 已核实；增量写范围；用户覆盖语录语言须注明。

## 成稿与增量

| 路径 | 做法 |
| :--- | :--- |
| **新建** | 读源之后**直接用中文**写；禁止先交夹写稿再「可选翻译」 |
| **增量** | 最小 diff：只改叙述层与语录夹写，不重排目录、不删数字。顺序：导读 → 洞察 → 正文 → 语录 |

翻译原则：译义不译词（*pricing power* → 定价权）；数字与专名不动；流程名可留 `Plan → Tool Call → Observe`，同段给中文；禁止 `inspect（inspectable）` 式括注顶替翻译。

## 易错译法（只列非字面）

其余 1:1 译法见 `lexicon.txt` 行内注释。下面这些**按语境**，不要无脑替换：

| 词 | 普通叙述 | 例外 |
| :--- | :--- | :--- |
| **rollout** | 发布 / 灰度推进 | 训练采样语境才写「采样轨迹」；禁止一律译「推广」 |
| **pitch** | 推销陈述 | 非体育场次 |
| **onboarding** | 新用户引导 | 产品模块正式名可留 onboarding |
| **demo** | 演示 | **Demo Day**、产品名保留 |
| **hook** | 钩子 | Cursor **Hooks**、git hook 对象名保留 |
| **checkout** | 检出 | `git checkout` 保留 |
| **spawn** | 启动 / 拉起 | API 名讨论可留 |
| **RAG / PIP / COGS / T&E / TAM** | 首现注中文全称 | 其后可裸用缩写 |
| **Harness / Evals / Builder / Agent Loop / Loop / Graph** | 不作机械替换 | 按四问与过译护栏 |

## 可读性内化（可选）

用户指定跨文化受众，或素材文化梗密集时启用。与简洁版/专栏模式可叠加。

1. 人物/机构/典故/俚语**首次**用短括注补背景，后文不重复。
2. 只增不删，不降信息密度。
3. 第三人称客观叙述；禁元叙述、禁「你们」说教（引语内除外）、禁「相当于国内 XX」。
4. 补注里的英文仍走专名层 + 4c。

自检「可读性内化」列举本篇实体；未启用填「不适用」。结构金样见 `fixtures/`。

## 存量复审

用户要优化已有 `*整理文档*.md` 时：先另存修订前副本 → 跑 `selfcheck.py` → 独立中文化语录（4c-3）→ 拆双层括注 → 过译专项（上表 + `over-translation-guard.md`）→ 4d → 4e → `selfcheck.py 新稿 --before 副本` 做 4f 比对并补回丢失内容 → 更新自检与文末生成时间（**不改文件名日期前缀**）。不要为复审重排目录。
