## 正文语言与英文保留边界【核心红线】

默认交付物是**中文深度文章**，不是「中文骨架 + 英文转写夹写」。**语义级高保真**指论点、数字、步骤、案例、比喻与张力**不丢**，**不等于**在叙述句里保留嘉宾的英文原词。

### 三层语言分区

| 层级 | 范围 | 语言规则 |
| :--- | :--- | :--- |
| **叙述层** | 导读、目录标题、各节正文、列表说明、Q&A 归纳句 | **以中文为主**写清含义；读者不应需要英文阅读能力才能跟读论证 |
| **专名 / 术语保真层** | 公司/产品/模型/API、已校准术语、行业固定缩写，以及讲者明确用作角色/范式/工作流原语/对照组的社区原生标签 | 保留**官方或社区通行英文写法**（如 **Claude Managed Agents**、**MCP**、**Messages API**、**Builder**、**Agent Loop**、**Loop / Graph**）；需要解释时首次中英并写，后文沿用标签。行业缩写首次出现须注中文全称「中文全称（英文缩写）」——MCP、API、LLM、SaaS 等已普及缩写可免注 |
| **档案层** | 元数据「原标题」、延伸术语表专名列、ASR 音译记录 | 可保留**原文英文**；**关键语录默认不在此层**——须译成中文 |

### 叙述层：必须中文化 vs 必须保真的英文

**必须译为中文**（不得仅加粗英文原词顶替）：

- 通用动作与状态：*fully auditable*、*convert to approval*、*shared workspace*、*minimalistic iteration*、*leak information*、*wake up*、*dogfooding* 等
- 通用名词短语：*outcome spec*（→ 产出规格）、*single player / multiplayer*（→ 单人试用 / 多人协作；首次可加英文括注）等；但若讲者把某词当作命名或范式标签（如 **Agent Loop**），转入下方术语保真规则
- 形容词与副词性口语：*actionable*、*highly optimized*、*immediate* 等（除非已是业界固定专名的一部分）

**必须保留英文或首现中英并写**（仍需符合术语校准表）：

- **品牌与产品正式名称**：OpenAI、Asana、Claude、**AI Teammates**
- **API / 协议 / 控制台能力名**：**Messages API**、**Model Context Protocol（MCP）**
- **讲者明确当作产品 UI 标签**且中文尚无统一译名的字段（首次：**中文说明 + 英文 UI 名**；后文可简称中文）
- **讲者明确当作角色、身份、范式、工作流原语、架构层或对照组的社区原生标签**：**Builder**、**Agent**、**Agent Loop**、**Loop**、**Graph**、**Workflow**、**Harness**、**Evals**、**Tool Call** 等。若原文把多个词并列成 taxonomy，整组保留其英文关系，不逐词翻掉
- **无法可靠译出的 ASR 音**（保留音并 `[ASR不确定]` / 编者注），不得用英文假装「更忠实」

#### AI/DevTools 概念标签的语境判定【v5.31】

不要再用「是不是官方产品名」作为唯一标准。依次问：

1. 这是产品、UI、命令、代码对象或文件名吗？是则保留英文。
2. 讲者是否在**命名一个概念**、声明自我身份、比较几种范式，或列举一套演化链？是则保留英文标签，首次可补中文解释。
3. 英文是否提供中文译法无法保留的可检索性或圈内指向？是则采用「中文说明（English）」或直接保留英文。
4. 以上都不是，只是普通动作、状态、形容或比喻，才翻成自然中文。

典型回归：

- ❌ `先是代理，然后循环，然后图` → ✅ `先是 Agent，接着是 Loop，再到 Graph`
- ❌ `他爱的是建造，编程只是手段`（原文强调 builder 身份）→ ✅ `他真正认同的是 Builder 身份；编程只是实现手段`
- ❌ 为通过 4c，把 **Agent Loop**、**Harness** 全部替换成中文 → ✅ 先判断它们是否承担标签/层名；仅普通语义才译

**克制原则**：术语保真不等于恢复整句英文，也不等于每次都加括号。一个标签首次解释一次即可；普通叙事仍写流畅中文。

### 首次出现与目录标题

- 口播 coined term（如 *multiplayer*、*agentic enterprise*）：正文首次写 **中文（English）** 或 **中文—英文专名**；后文以中文为主，避免同段重复英文。
- **目录与小节标题默认中文**，须含实质关键词；禁止整节标题仅用英文短语（元数据「原标题」除外）。

### 局部加粗（与语言规则联动）

- **加粗对象**：中文结论、**关键数字**、**专名层实体**、绝妙比喻——**不要**把整句英文状语/动词短语加粗后塞进中文句。
- **反模式**：`**Shared workspace**里 **prompts & threads**…`（转写稿式中英夹写）→ 应写「**共享工作区**内的人机 **提示词与对话线程**…」

### 与高保真、风格保留的关系

- **风格保留**：比喻、幽默、锋芒通过**中文复述**与**关键语录区中文译文**呈现；不要在叙述层堆英文来「保留口吻」。
- **用户显式要求**「保留英文原文 / 中英双语」时，可覆盖本节；须在自检注明覆盖项。双语格式全文一致：**中文主句** + 换行 `（原文："…"）` 或并列块引用，二选一。

### 常见失败模式（转写式夹写）【v5.17 强化】

以下模式在英文源逐字稿整理中**高频出现**，一律视为**质量缺陷**，不是「高保真」：

| 失败模式 | 典型表现 | 规范写法 |
| :--- | :--- | :--- |
| **加粗英文顶替翻译** | `**operationalize**`、`**super bullish**` 嵌在中文句 | 写「**落地执行**」「**极度看好**」 |
| **核心洞察英文化** | `> **Dan Shipper super bullish on PMs…**` | 洞察块**必须全中文**；原话进「关键语录」 |
| **半句英文半句中文** | `重组有，**mass unemployment** 无` | `重组会有，但不会出现**大规模失业**` |
| **口语动词不译** | `panic`、`reorganize`、`settle`、`flip` | 慌了、重组、趋于稳定、偶尔切换 |
| **把 coined term 当正文主体** | 正文反复 `ride the models` 不加中文 | 首次「**骑在模型上（ride the models）**」，后文以中文为主 |
| **误标自检** | 正文大量夹写却写「正文中文叙事 ✅」 | 须先跑 4c 检索，有命中则 ⚠️ 并写修正处数 |
| **误标排版** | 正文节间堆 `---`/三连空行却写「纯净排版 ✅」 | 须先跑 **4d 节间空白闸门**；违规 >0 则 ⚠️ 并写计数 |
| **呼吸感误读** | 为「呼吸感」在 `##` 下留 3–4 空行、每节后加 `---` | **段内**短段落=呼吸感；**节间**仅单空行、禁 `---` |
| **高保真误读** | 为「保留口吻」在叙述层堆 `refine`/`holistic` 等普通英文；或反过来把 **Builder / Agent Loop / Loop / Graph** 等概念标签翻没 | 普通语义用中文复述；概念标签按 v5.31 保留英文或首现中英并写 |
| **括注式夹写** | `great products（伟大产品）` 或整句英文+中文括注 | 正文写中文；首次 coined term 才用「中文（English）」 |

**Dan Shipper 类反例（错误 → 正确）**：

- ❌ `仍坚持 **human writing important**` → ✅ `仍坚持**人类写作仍然重要**`
- ❌ `> **The only thing you need to do is ride the models——好奇、 playful…**` → ✅ `> **生存策略只有一条：骑在模型上——保持好奇、 playful 地试用新模型…**`（`playful` 若保留须首次括注）
- ❌ `便于 **operationalize**（Agent 秒读万页，人类讲 story）` → ✅ `便于**把长文知识落地到日常工作**（Agent 可秒读万页，人类负责讲清叙事主线）`

### 核心洞察 vs 关键语录 vs 对谈实录（硬分层）【v5.19；v5.23 扩展】

- **`### 核心洞察` 块**：**禁止**整句或半句英文口播；须用 **1–2 句中文**写清结论（≤50 字为宜）。
- **`### 深度解析` 块**：分析师口吻展开论点、数字、因果；可含**单次**块引用 `> **{全名}**：「…」`，但**不得**用大段引语代替解析。
- **`### 对谈实录` 块**（启用「对谈三层节结构」时）：精编多人 Q&A，格式 `**{全名}**：「…」` 逐说话人换行；**默认中文译文**（专名层保留英文）；语义、张力、幽默须落地，**不得**字幕逐字复读或堆英文。4c 规则**同关键语录**。
- **`## 关键语录与交锋时刻`**（**未**启用对谈三层时）：**默认中文译文**（专名层保留英文）；启用对谈三层时**省略本篇末节**，金句已沉入各节 **对谈实录**——用户显式要求保留时可并存，但不得与实录大段重复。

### 步骤 4c：叙述层中文化强制检索【v5.17；v5.22 强化验收闸门】

成稿后、写自检前，对**导读 + 目录标题 + 各节深度解析 + 核心洞察 + 对谈实录 + 关键语录**（**排除**元数据「原标题」、术语表专名列、用户显式要求保留英文的双语原文副行）执行：

1. **全文通读**：任一中文句若含 **≥2 个连续英文单词**，先判定它是普通英语还是专名/社区原生概念标签；前者改中文，后者保留并检查是否需要首次释义。
2. **模式检索**（命中先判指称）：对 **`references/lexicon.txt`**（统一词库单源）执行 grep，或直接运行 `scripts/check_4c.py`。`super bullish`、`operationalize`、`holistic`、`refine` 等普通用法命中即改；多义技术词不得仅凭词库命中机械翻译。
3. **核心洞察专项检查**：每个 `### 核心洞察` 下 `>` 块不得含英文谓语串（允许 **GPT-5.5**、**SaaS** 等专名）。
4. **关键语录 / 对谈实录专项检查（4c-3）**：若启用**对谈三层节结构**，逐节扫描各 `### 对谈实录`；否则扫描 `## 关键语录与交锋时刻`。均须**全中文译文**（专名层除外）；不得保留 `unaware`、`disposable`、`craft`、`vibe` 等通用英文谓语/形容词。
5. **统计**：自检「正文中文叙事」行须写 **grep 命中 X 处 → 修正后 Y 处**（或 **`⚠️ 存量夹写 M 处待补丁`**）；**Y > 0 且仍有 M>0 时不得标 ✅**。
6. **验收闸门**：见下节「4c 验收闸门」——**未过闸门禁止标 ✅**。

### 4c 验收闸门【v5.22】

写自检「正文中文叙事 ✅」前，**必须**完成下列三步；任一步未做或未记录，视为**误标自检**：

| 步骤 | 动作 | 通过标准 |
| :--- | :--- | :--- |
| **4c-1 词库 grep** | 对 `references/lexicon.txt`（统一词库单源）grep 全文，或运行 `scripts/check_4c.py`（排除元数据原标题、术语表专名列） | 叙述层+关键语录中**裸露通用夹写词为 0**（专名层除外）。**不计入失败**：① 首现合法括注 `中文（English）` / `（English）` 内的词库词；② `references/over-translation-guard.md` 白名单专名（如 **Skill** / **Skill Creator** / **Claude Code**） |
| **4c-2 连续英文扫描** | 通读导读/正文/核心洞察/关键语录，找 **≥2 连续英文单词** 的非术语短语 | 命中须改中文或确认为专名/概念标签；不得留 `refine`、`holistic` 等普通夹写；**同时反向检查过译**（勿把 Skill/Creator、Builder、Agent Loop、Loop/Graph taxonomy 等译没） |
| **4c-3 关键语录 / 对谈实录独立扫** | 启用**对谈三层**时逐节扫 `### 对谈实录`；否则扫 `## 关键语录` | 无英文半句/整句（专名、产品型号除外） |

**可选自动化**：成稿后可运行本技能内 `scripts/check_4c.py {文件路径}`（词库全量加载自 `references/lexicon.txt`，与 4c-1 手工 grep 同源）。脚本分三类输出：`ACTIONABLE_HITS`（明确普通夹写，未清零不得标 ✅）、`CONTEXTUAL_ENGLISH_REVIEW`（多义技术词，须按来源判断保留或翻译）、`OVER_TRANSLATION_REVIEW`（疑似把英文概念标签翻没，须回看原文）。后两类是**人工复核提示**，允许核实后保留，但不得未看就忽略。**脚本 0 命中不能替代 4c-2 通读与过译护栏**。勿依赖已移除的 `.cursor/tmp/output_full_audit.py`。

**自检备注格式（新建稿）**：`✅ 4c 闸门通过；裸词 grep 命中 {X}→修正后 {Y}；多义术语 {C} 项、疑似过译 {R} 项已对照来源逐项核实；括注/术语白名单已排除；金句/实录已译中文`

### 步骤 4d：节间空白验收闸门【v5.25】

写自检「纯净排版 ✅」前，**必须**完成下列检查；任一项未做或未记录，视为**误标排版**（与 4c 误标同级）：

| 步骤 | 动作 | 通过标准 |
| :--- | :--- | :--- |
| **4d-1 `---` 计数** | 全文 grep `^---$`（或运行 `scripts/normalize_spacing.py --check`） | 全文 **`---` 共 ≤6 处**，且**仅**出现在：元数据块后、导读后、目录后、**关键语录与交锋时刻前（通用模板）**、延伸术语表前、自检报告前；**正文 `##` 主题节之间为 0** |
| **4d-2 三连空行** | grep 连续 `\n\n\n+` 或脚本 `--check` | **0 处**三连及以上空行（`##`→`### 核心洞察` 之间亦禁止） |
| **4d-3 `##`→`###` 间距** | 逐节核对每个正文 `##` 标题与首个 `###` 之间 | **恰好 1 个空行**（对谈三层：首个 `###` 应为 `核心洞察`） |

**可选自动化**：成稿或存量优化后，运行本技能内 `scripts/normalize_spacing.py {文件路径}` 自动修正；`--check` 仅报告不写入。**脚本通过不能替代 4d-3 目视**，但 `--check` 失败时**不得标 ✅**。

**自检备注格式（新建稿）**：`✅ 4d 闸门通过；--- 共 {N} 处（≤6）；正文节间 --- 0；三连空行 0`

**存量优化**：按「存量 output 优化检查清单」第 7 条 + 本闸门；修正后更新「纯净排版」行。

### 专名层误判清单（4c 须改中文）【v5.22；v5.32 词表外置】

高频误判词（`refine`、`holistic`、`aware/unaware`、`storytelling`、`craft`、`vibe`、`persona` 等）**不是**品牌/产品专名，**不得**以「高保真」「业界固定说法」为由留在叙述层或关键语录——须译成中文（首次 coined term 可用「中文（English）」，后文中文）。

**词表单一来源**：完整清单见 **`references/lexicon.txt`**（`[blocking]` 节 = 裸露即失败；`[contextual]` 节 = 按语境判定）。本 spec 不再维护词表副本；新词只加进 `lexicon.txt`，`scripts/check_4c.py` 会自动加载。

**允许保留英文的典型专名层**（非穷举）：**OpenAI**、**Claude Code**、**Skill** / **Agent Skill** / **Skill Creator**、**Hooks**、**Computer Use**、**Composer**、**Canvas**、**iPhone**、**Tony Fadell**、**B2B**/**B2C**、**Wi-Fi**、**LLM**、书名《Build》、元数据「原标题」。机器可读白名单见 `lexicon.txt` `[allow]` / `[allow-case-sensitive]` 节；完整过译黑名单见 `references/over-translation-guard.md`。

### 存量 output 稿件增量中文化【v5.17】

用户要求「优化 output 已有文档」时：

- **最小 diff**：只改叙述层夹写，**不重排目录、不删案例数字、不改专名校准**。
- **顺序**：先改 **核心导读 + 核心洞察**，再改正文段落，**关键语录中文化**，术语表专名列可保留英文。
- **批次**：按文件逐个处理；每文件改完后更新该文件自检表「正文中文叙事」行。
- **验收**：该文件叙述层 4c 检索命中数应 **显著下降**（目标：通用英文短语命中为 0；专名层除外）。

### 默认中文化工作流（成稿即中文）【v5.18】

**默认行为**：凡触发本技能，交付物**从第一稿起就是中文深度文章**——叙述层与**关键语录**均中文，不是先写中英夹写再「可选翻译」。用户**无需**再说「翻译成中文」；仅当用户显式要求「保留英文原文 / 中英双语」时才覆盖关键语录语言。

#### 成稿路径（二选一，勿混用）

| 路径 | 何时 | 做法 |
| :--- | :--- | :--- |
| **A. 新建整理** | 用户提供 URL、字幕、逐字稿，要求输出整理文档 | 读英文/混合源 → **直接用中文**写导读、正文、核心洞察、**关键语录**、目录标题 |
| **B. 增量中文化** | 用户指定 output 已有稿某段，或说「优化/翻译某节」 | **最小 diff**：改叙述层夹写 + **关键语录中文化**；不重排目录、不删数字；顺序：导读 → 核心洞察 → 正文 → 关键语录 |

**禁止路径**：先产出「中文骨架 + 英文口播词」再交付——这属于转写稿，不是本技能默认交付物。

#### 三层语言：默认怎么译

默认分区同上文「正文语言与英文保留边界 > 三层语言分区」（**叙述层**中文 / **专名层**官方英文 / **档案层**可留原文）。本工作流下额外明确：

- **核心洞察**与**关键语录**归**叙述层**，默认中文。
- 元数据「原标题」保留原文；**文件名 `{内容标题}` 基于原标题译写/保留信息**（非中文默认译成中文），见「文件命名规则」。
- 延伸术语表**以中文解释为主**，术语列可保留英文专名。

**用户显式覆盖**（须在自检注明）：

- 「**保留英文原文**」→ 关键语录保留英文，叙述层仍中文
- 「**中英双语**」→ 关键语录中文主句 + `（原文："…"）` 副行，或并列双语块，全文一致

#### 翻译原则（语义保真，非逐词转写）

1. **译义不译词**：*pricing power* → 定价权；*margin* → 利润率/毛利；*distribution matters* → 分发才重要——**禁止** `**pricing power**` 嵌在中文句里冒充高保真。
2. **数字与专名不动**：口播整数、百分比、金额、产品型号、人名全名——与原文一致，不静默改写。
3. **风格用中文复述**：比喻、幽默、锋芒、对谈张力写进中文正文；**不要**在叙述层堆英文保留「口吻」。
4. **固定流程名**：*Plan → Tool Call → Observe → Refine* 等可保留箭头英文，须**同段给出中文**（计划 → 工具调用 → 观察 → 修正）。
5. ** coined 术语**：首次 **中文（English）**，后文中文为主（如 **套壳（wrappers）**、**劳动总量谬误（lump of labor fallacy）**）。
6. **禁止「英文括注顶替翻译」**：❌ `可 inspect（inspectable）` → ✅ `可审阅`；❌ `撰写并 refine` → ✅ `撰写并迭代精修`。
7. **核心洞察硬规则**：`### 核心洞察` 块**零英文谓语**；段内单次引用与**关键语录**默认中文，用户要求双语时英文仅作原文副行。

#### 英文源素材高频夹写词（统一词库：4c 强制检索 + 成稿主动译）【v5.32 外置】

**词库单一来源为 `references/lexicon.txt`**（本 spec 不再维护词表副本）。它同时服务两个动作：

- **4c-1 强制 grep**：对 `lexicon.txt` 的 **`[blocking]`**（裸露即失败）与 **`[contextual]`**（按语境判定）两节全量检索——直接运行 `scripts/check_4c.py {文件}` 即等价执行（脚本自动加载全表并排除首现括注、`[allow]` 白名单、链接与代码块）。
- **成稿主动译**：整理**英文播客/博客/访谈**时，叙述层遇到这些词（非专名用法）应主动译为中文，而不是等 grep 兜底。

新词**只加进 `lexicon.txt`** 对应分节；分节语义与格式说明见该文件头部注释。

> **播客/创投/企业销售扩展词译法**（词已收录于 `lexicon.txt`，此处只保留中文译法指导）：`COGS`→销货成本、`down-rev`→向下修订、`term sheet`→投资条款清单、`offer letter`→录用通知书、`outbound/inbound`→外呼/入站线索、`PIP`→绩效改进计划、`T&E`→差旅与招待报销、`containment`→隔离边界、`pitch`→推销陈述（非体育）、`rep`→销售代表、`onboarding`→新用户引导（**产品模块正式名可保留 onboarding**）、`refinement`→微调、`rollout`→**按语境**：产品发布/灰度推进；仅在训练/推理采样语境才用「采样轨迹」；（**禁止**无脑译「推广」）、`demo`→演示（**Demo Day** 等专名保留）、`live demo`→现场演示、`one-shot prompt`→单次提示词。

> **AI / DevTools 行话簇【v5.31，整理技术/开发者素材必跑】**：下列映射只适用于**普通叙述义**，若词在原文中承担产品对象、代码对象、角色、范式或架构层标签，转入术语保真层，不机械替换。`dogfood/dogfooding`→内部试用、`oneshot/one-shot`→一次成功、`flaky`→不稳定（测试）、`ration`→限额/配给、`tally`→记一笔/统计、`spawn`→启动/拉起（**API 名讨论可保留**）、`checkout`→检出（**`git checkout` 保留**）、`hook`→钩子（**Cursor Hooks 产品名保留 Hooks**）、`subprocess`→子进程、`RAG`→检索增强生成（缩写可留，须首现全称）、`chassis`→底盘、`wrapper`→封装层/套壳、`bare-bones`→极简、`launch review`→上线评审、`latent demand`→潜在需求、`roadmap`→路线图、`standup`→每日站会、`moderation`→人工审核、`primitive`→原语、`craze`→狂热、`secret sauce`→独门秘方、`source available`→源码可见。**Harness / Evals / Builder / Agent Loop / Loop / Graph** 不列作机械替换项，按指称判断。
>
> **专名 vs 行话判定原则【v5.31】**：**保留英文**——产品/工具/协议/模型/命令名与技术对象名（`Claude Code`、`MCP`、`Opus 4.5`、`/loop`、`worktree`、`tmux`、`bash`、`PR`、`CI`、**`Skill` / `Agent Skill` / `Skill Creator`**、**`Hooks`**、**`Computer Use`**、**`Composer`**、**`Canvas`**、**`Subagent`**），以及讲者用作角色、身份、范式、工作流原语或对照组的社区原生标签（**`Builder`、`Agent`、`Agent Loop`、`Loop`、`Graph`、`Workflow`、`Harness`、`Evals`**）。**中文化**——普通行为、状态、口语形容词与不承担标签作用的通用名词短语。拿不准时不能只问「是不是官方名字」，还要问「讲者是否在用它命名一个概念或一组 taxonomy」；若是，英文标签保留，首次可补中文说明。详见 `references/over-translation-guard.md`。

#### 4c 检索范围（强制）

成稿或增量补丁后，对下列范围执行 grep + 通读（**专名层除外**）：

- 导读、目录标题、各节 **深度解析**、**核心洞察**、**对谈实录**、**关键语录**
- **排除**：元数据「原标题」、术语表专名列、用户显式要求保留的「原文：…」副行

命中 ≥2 连续英文单词的非专名短语 → 改中文；统计修正处数写入自检「正文中文叙事」行。

#### 自检写法（v5.18）

| 场景 | 「正文中文叙事」行 |
| :--- | :--- |
| 新建稿 | `✅ 4c 闸门通过；裸词 grep 命中 X→修正后 Y；多义术语 C 项、疑似过译 R 项已对照来源逐项核实；括注/术语白名单已排除；关键语录已译中文` |
| 增量中文化 | `✅ 增量中文化 {范围}；裸词 grep 命中 X→修正后 Y；关键语录中文化 M 条；无过译专名` |
| 用户要求保留英文金句 | `✅ 叙述层中文；关键语录保留英文（用户覆盖）` |
| 用户要求双语金句 | `✅ 叙述层中文；关键语录中英双语（用户覆盖）` |
| 仍有夹写 | `⚠️ 存量夹写 M 处待补丁（列出典型词）；4c 闸门未通过` |
| 误标（禁止） | 未跑 4c-1/4c-2/4c-3 即写 `已修正 N 处 ✅` |

**禁止**无 4c 检索即标 ✅。**禁止**只修正少量夹写却宣称「4c 已执行 ✅」而正文仍含通用英文词（见「专名层误判清单」）。

## 可读性内化适配（受众导向，可选）【v5.20】

**用途**：当素材**文化梗密集、异国语境强**，或**目标读者与原文默认读者存在文化/语境落差**时，启用本模式，让目标读者**无需另行检索**即可读懂全文，同时**不牺牲信息密度**。属**可选适配模式**：由用户显式指定受众（如「**中国公民、赴美大一、熟悉课堂英文但不熟悉美国文化梗与高校语境**」），或在素材明显跨文化时建议启用；可与「简洁版」「专栏文章模式」等其他偏好叠加。

### 适配规则

1. **首次出现处补背景**：人物、机构、作品、典故、俚语、校园/行业「梗」**首次出现**时，用**简短括注或破折号插入语**补足背景（谁、是什么、为何相关）；同一实体后文不再重复解释，避免堆叠注释拖慢节奏。
2. **叙述层中文、专名保留**：背景注释用**中文**写，专名按「三层语言分区」保留官方英文；补背景属**增信息**，不改既有术语校准与专名写法。
3. **不降信息密度（只增不删）**：补背景**只能加注、不得删节**——原有论点、数字、案例、比喻、张力一律保留；**禁止**借「便于理解」之名压缩或丢弃原意。
4. **客观深度稿口吻**：背景与转述用**第三人称客观叙述**（与「称谓与署名」全名规则一致），读感是《连线》式报道，而非课堂讲义或导游词。
5. **禁止元叙述**：不得写「本节将…」「下面我们来看…」「读者应注意…」「译者注：为帮助理解…」等**自指/导览/对读者喊话**句；背景信息**直接融入行文**。
6. **禁止第二人称说教**：叙述层**不得**用「你 / 你们」做训导或代入（如「你要记住…」）；**第二人称仅可出现在直接引语内**（保留讲者原话里的「你们」）。
7. **禁止国内场景硬类比**：**不得**用「相当于国内的 XX」「类似我们这边的 XX」等牵强本土类比解释异国概念；改用**中性、准确的客观说明**（如「**final club**：哈佛历史悠久、门槛极高、不对外开放的男性私宴会所」）。

### 与 4c、自检集成

- 补注内的英文专名仍走**专名层 + 术语校准**；成稿后照常执行**步骤 4c**（背景注释里的通用英文短语同样须中文化）。
- 自检表**新增「可读性内化」行**，须写明：首次背景补注覆盖范围（典型实体列举）、口吻是否客观第三人称、第二人称是否仅存于引语、有无元叙述/国内硬类比残留；**未启用**本模式时填「不适用」。
- 参考成稿样例（若工作区存在）：`output/20260529_柯南·奥布莱恩哈佛大学2026毕业典礼演讲_整理文档.md`（赴美大一受众适配范例）；结构金样见本技能 `fixtures/`。

### 体裁快速补注（存量优化常用）

| 体裁 | 首次出现建议补注 |
| :--- | :--- |

## 存量 output 优化检查清单【v5.21】

### 分档标准

| 档位 | 标准 |
| :--- | :--- |
| **A** | **4c 验收闸门通过**（grep 0 命中 + 连续英文扫描 0 + 关键语录全中文）；可读性内化有**具体实体列举**；自检写 **grep X→Y** 且准确 |

### 建议批次顺序

1. 创投/商业播客（**20VC**、**All-In**、**MAD**）
2. **AI Engineer** / **Code with Claude**
3. 毕业典礼 / 论坛 / 主题演讲
4. 长访谈（**Thibault**、**Decoder**、**Hard Fork**、**Matt Berman** 等）

### 单篇 A 档必做（6 步）

1. **grep + 闸门**：对 `references/lexicon.txt` 全量 grep（或运行 `scripts/check_4c.py`）；过 **4c 验收闸门**（见上节）。
2. **关键语录**：`## 关键语录` 区块**独立**逐条中文化（4c-3）；引语内专名保留英文。
3. **嵌套修复**：检查重复括注（如 `氛围编程（…氛围编程…）`、`凭感觉编码` 双层嵌套）。
4. **可读性内化**：将自检「播客/访谈体裁：首次补行业专名…」替换为**本篇具体实体**（节目名、高校传统、展会名等）。
5. **误译/过译专项**：`rollout`≠推广（发布/灰度 vs 采样轨迹按语境）；`pitch` 按语境；**Code Review/PR/CI** 可保留；**Skill / Skill Creator / Hooks / Computer Use** 禁止译成「技能/技能创建者/钩子/电脑使用」等（见过译护栏）。
6. **自检更新**：`叙述层已修正 N 处`、可读性内化 ✅ 备注、`*文档生成时间*`（勿改文件名日期前缀）。
7. **节间空白【v5.24/v5.25】**：删除正文各 `##` 节之间的 `---`；`##` 与 `### 核心洞察` 之间仅保留**一行空行**；对谈三层稿删除节标题下过渡段；过 **4d 节间空白验收闸门** 后更新自检。
