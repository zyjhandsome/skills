# 转换、告警与已有页面维护

在处理 WARN、调整页头、补 Mermaid、重命名或迁移旧页面时读取。

## 首次转换与升级契约

`build_html.py input.md [output.html]` 默认生成同目录、同文件名的 `.html`。
它直接写入输出，不能保存已有页面中的人工图示；输出已存在且有人工编辑时，
先使用升级脚本或生成到另一个路径。

`batch_upgrade_dir.py <directory> [--glob <pattern>] [--build <converter>]`
递归寻找含讲义生成标记、且有同名 `.md` 的 `.html`，跳过其他页面。
输入结构决定是否适用，不限 `_整理文档` 后缀；公众号粘贴 HTML 不属于讲义。
`--glob` 是 HTML 文件名模式，`--build` 默认使用同目录转换器。

每个页面先在原目录生成临时文件，全部图示恢复、结构校验和告警检查通过后，
再原子替换旧页面。临时文件在完成或失败后清理。一个页面失败不妨碍其他页面
继续，但总退出码为非零，必须报告失败文件。

升级的 FAIL 包括：

- 转换器退出失败、输出不完整或没有报告章节数。
- 任何源稿 WARN 未处理。
- 图示无法分配到唯一章节，或保存/恢复数不一致。
- 新页面章节数不符、id 重复或目录缺失目标。
- 转换期间源稿或旧 HTML 被其他编辑修改。

## WARN 的处理

单文件转换打印 `sections`、CJK 字数和估算阅读时长；WARN 表示产物还需复核。
升级流程会透传这些告警并保留旧页面。

| 告警 | 处理 |
|---|---|
| missing required section | 恢复 `文章元数据` 或 `核心导读`，核对是否为完整整理稿 |
| no source URL | 核实并恢复内容链接，不自行填入猜测来源 |
| none is marked「主持」 | 核实角色后在人物说明中标注主持；无主持的真实多人场景需报告，不能为配色改事实 |
| duplicated blockquote | 对照源稿核实重复，避免删掉有意重复的证据 |
| editor note | 将 ASR/核对等过程说明移回自检；必要的读者限定说明保留并核实 |
| unclosed editor note | 修复跨空行未收口的括注，不改变其中事实或归属 |
| orphan closing bracket | 将单独的 `]` / `］` 归回对应括注 |
| bracket leaked into dialogue | 修复以 `]` / `］` 开头的伪发言，禁止把编者句子当引语 |

短标记 `［预测］［编者推断］［主持人口播］` 是读者信息，不因其存在而删除。
已闭合的半角 `[编者注：…]` 不会被转换器改写。代码围栏中的示例不会触发括注告警。
告警无法核实处理时，将结果保留为待验收，不声明发布完成。

## 页头调整如何保留

| 字段 | 自动推导依据 |
|---|---|
| 页面 `<title>` / `doc-title` | Markdown 一级标题 |
| `doc-eyebrow` | 文稿结构、人物数，显示对谈笔记或整理笔记 |
| `doc-subtitle` | 默认留空，全文论点已在导读展示，不重复填入 |
| 来源短行 | 活动/节目短名，否则主持人说明或原标题；再拼人物名 |
| 日期 | 发布时间，页头去掉口径/抓取括注和分号尾部，元数据面板保留完整字段 |
| 阅读时长 | 阅读路径中的 CJK 字数 ÷ 300，估算值 |

允许直接微调生成 HTML 的页头。新页面含 `lecture-header-defaults` JSON 记录，
升级将字段当前值与自动值比较：被改过的保留，未改过的随新源稿更新。
保留范围是页面标题、可见标题、眉题、副标题、来源短行和日期。
不要手工编辑该记录；损坏记录会阻止升级。

没有记录的历史页面无法可靠判断哪些字段曾被编辑，因此迁移时保留现有页头。
希望重新推导全部页头时使用：

```bash
python "<skill-dir>/scripts/batch_upgrade_dir.py" "<notes-dir>" --glob "<name>.html" --refresh-header
```

此选项会放弃这些页头调整，但仍要求保留全部图示。阅读时长、来源链接和页脚
源文件名始终从新源稿计算；正文手工改写不在升级保留范围内，应回到 `.md`。

## Mermaid 图示

在结论之后放图，不重复已有对照表。保持小图，只使用源稿支持的关系。

```html
<figure class="diagram">
  <pre class="mermaid">
flowchart LR
  A[收集申请] --> B[审核]
  B --> C["批准、补充材料"]
  B -. 尚未建立 .-> D[后续跟踪]
  </pre>
  <figcaption class="diagram-caption">审核后的去向与尚未建立的跟踪环节。</figcaption>
</figure>
```

通常 3–6 个节点。顺序用 `flowchart LR`，分支用 `flowchart TD`。
标点放在 `["…"]` 中，不把并列名词粘成一串。缺失关系用带说明的虚线。
离线降级支持这种逐行、方括号节点、实线/虚线边的小流程图；其他 Mermaid
语法不保证有文本降级，应提供可独立理解的图注并做实际验证。

升级保留每个章节内所有 `figure.diagram`，并移到核心洞察之后。
对应关系依赖章节 id；章节改名、删除或锚点变更时，升级失败并保留旧页面。
不要按章节位置猜测图的归属。在副本中核实并迁移图表到正确的新章节，再验收。

## 重命名与旧 CSS

源 `.md` 改名后，将对应 `.html` 改成同名并升级；页脚来源会更新。
章节标题改名与文件名改名不同，前者可能改变图表锚点。
若本次任务还包含 `md2wechat` 产物，按该 Skill 的指纹与文件名规则重新生成。

`scripts/patch_key_emphasis.py` 只用于关键强调样式迁移前生成的旧 HTML：

```bash
python "<skill-dir>/scripts/patch_key_emphasis.py" "<old-html-or-dir>"
```

当前模板已含这些样式，新产物无需再补丁。能正常升级的讲义优先使用升级脚本。
